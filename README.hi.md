# एक 32B QLoRA मॉडल को या एक 7B एंड-टू-एंड मॉडल को एक ही जीपीयू पर बेहतर बनाएं। फिर इसे ओलामा में भेजें।

बैकप्रोपैगेट, आपके पास मौजूद हार्डवेयर के अनुसार, एक **एकल** जीपीयू पर बड़े भाषा मॉडल को बेहतर बनाता है। तीन पंक्तियों के पायथन कोड QLoRA से 7B–32B मॉडल को एक 32 जीबी उपभोक्ता कार्ड (आरटीएक्स 5090) पर चलाया जा सकता है। एक ध्वज, `--full-ft-offload`, 7B-श्रेणी के मॉडल को उसके भार और ग्रेडिएंट को होस्ट रैम (लिनक्स या WSL2) में रखकर पूरी तरह से बेहतर बनाता है (यह धीमा है, और इसका माप नीचे दिया गया है)। एक और कमांड इसे ओलामा में निर्यात करता है, फिर `ollama run` आपके बेहतर मॉडल को। यह 16 जीबी तक कम किया जा सकता है। विंडोज पर यह उत्कृष्ट रूप से काम करता है। क्या आप पायथन के बजाय ब्राउज़र पसंद करते हैं? `backprop ui` बिना किसी कोड के यह सब करता है ([यहां देखें](https://mcp-tool-shop-org.github.io/backpropagate/handbook/web-ui/))।

```python
from backpropagate import Trainer

trainer = Trainer("Qwen/Qwen2.5-7B-Instruct")
trainer.train("my_data.jsonl", steps=100)
trainer.export("gguf", quantization="q4_k_m")
```

```bash
backprop export ./output --format gguf --quantization q4_k_m --ollama --ollama-name my-model
ollama run my-model
```

बस इतना ही। कोई YAML कॉन्फ़िग फ़ाइल नहीं है। कोई `accelerate launch` प्रक्रिया नहीं है। कोई अलग से “अब इसे GGUF में बदलें” ट्यूटोरियल नहीं है। यदि आपके पास एक CUDA GPU और आपके प्रशिक्षण डेटा वाली JSONL फ़ाइल है, तो आप एक कार्यात्मक फ़ाइनट्यून से केवल तीन चरणों की दूरी पर हैं।

## स्थापित करें

```bash
# Recommended: isolated Python install (no conflicts with system Python or other projects)
pipx install backpropagate

# Or via uv (faster install, same isolation)
uv tool install backpropagate

# Standard pip (if you manage your own virtualenv)
pip install backpropagate
```

यदि आप अतिरिक्त सुविधाओं का उपयोग करना चाहते हैं, तो इंस्टॉलेशन के दौरान इनमें से किसी एक विकल्प का चयन करें:

```bash
pipx install "backpropagate[standard]"   # adds Unsloth (2x faster training) + the web UI
pipx install "backpropagate[full]"       # adds everything: unsloth, ui, monitoring, export, etc.
```

क्या आप डॉकर पसंद करते हैं? `docker pull ghcr.io/mcp-tool-shop-org/backpropagate:latest` भी काम करेगा। `linux/amd64` और `linux/arm64` दोनों के लिए इमेज उपलब्ध हैं, इसलिए ऐप्पल सिलिकॉन और एआरएम लिनक्स उपयोगकर्ताओं को एक मूल इमेज मिलेगी। "कंटेनर में यूआई" के लिए एक मानक `compose.yaml` रिपॉजिटरी की जड़ में मौजूद है: इसे `user:password` को `ui-auth.txt` में रखें, `docker compose up` चलाएं, और `http://127.0.0.1:7860` पर साइन इन करें (पहली बार चलाने पर फ्रंटएंड बनाया जाता है, जिसमें एक या दो मिनट लगते हैं)। रन हिस्ट्री `~/.backpropagate` में बनी रहती है।

## बैकप्रोपैगेट किस स्थान पर स्थित है।

एलएलएम को बेहतर बनाने के लिए कई अच्छे पुस्तकालय उपलब्ध हैं। वे सभी अलग-अलग कार्यों में उत्कृष्ट हैं:

- **[एक्सोलोटल](https://github.com/OpenAccess-AI-Collective/axolotl)** — यदि आपको YAML कॉन्फ़िग पसंद हैं और आप व्यंजनों का एक ऐसा संग्रह चाहते हैं जिससे आप प्रेरणा ले सकें।
- **[LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory)** — यदि आप DPO/PPO/RLHF और एक वेब GUI चाहते हैं।
- **[अनस्लोथ](https://github.com/unslothai/unsloth)** — यदि आपको सबसे तेज़ प्रशिक्षण की आवश्यकता है और आप समर्थित मॉडल परिवार का उपयोग कर रहे हैं।
- **[टॉर्चट्यून](https://github.com/pytorch/torchtune)** — यदि आप मेटा के पहले संस्करण के PyTorch-आधारित व्यंजनों को संपादित करना चाहते हैं।

बैकप्रोपैगेट वह छूटा हुआ विकल्प है: **एकल उपभोक्ता जीपीयू पर काम करने वाले और एक एडाप्टर को प्रशिक्षित करके उसे उपयोग के लिए तैयार करने वाले स्वतंत्र ऑपरेटरों के लिए एक 3-पंक्ति वाला पायथन एपीआई।** इसमें कोई वाईएएमएल, कोई ऑनलाइन आरएल (पीपीओ/जीआरपीओ) और कोई मल्टी-नोड शामिल नहीं है। यदि आप कोड लिखना नहीं चाहते हैं, तो उसी प्रक्रिया के लिए एक ब्राउज़र यूआई उपलब्ध है। इसमें केवल वही प्रक्रिया शामिल है जिसकी वास्तव में आवश्यकता है और वह निर्यात चरण भी, जो बाधा उत्पन्न करता है।

यदि आपने ऊपर दिए गए किसी एक लाइब्रेरी का उपयोग करने की कोशिश की और कॉन्फ़िग-फ़ाइल सेट करने की प्रक्रिया में कोई समस्या आई, या मॉडल-परिवार में कोई अंतर पाया, या यदि आप चाहते हैं कि डिफ़ॉल्ट सेटिंग्स विंडोज़ के लिए हों — तो बैकप्रोपैगेट आपके लिए है।

## आप एक जीपीयू पर क्या-क्या चीजें बारीकी से समायोजित कर सकते हैं।

बैकप्रोपैगेट आपके कार्ड पर रन के आकार को समायोजित करता है। ये 32 जीबीआरटीएक्स 5090 पर मापे गए आंकड़े हैं: 2026-10-03 से QLoRA पंक्तियाँ (रसीदें: [`docs/receipts/2026-10-03-presets/`](docs/receipts/2026-10-03-presets/)), और 2026-09-30 से पूरी फाइन-ट्यूनिंग पंक्तियाँ (रसीदें: [`docs/receipts/2026-09-30-offload/`](docs/receipts/2026-09-30-offload/))। QLoRA शिखर पूर्वनिर्धारित की पूर्ण संदर्भ विंडो में बैच 1 के साथ हैं, जो उस पूर्वनिर्धारित के लिए सबसे खराब स्थिति है; छोटे उदाहरणों में कम डेटा का उपयोग किया जाता है।

| मॉडल | विधि | 32 जीबी कार्ड पर मापा गया। |
|---|---|---|
| **14बी** (Qwen2.5-14B) | QLoRA | **18.7 GiB** 4096 संदर्भ पर अधिकतम (20.0 GiB आरक्षित)। |
| 24बी (Mistral-Small-24B) | QLoRA | 22.8 GiB, 4096 संदर्भ में अधिकतम मान, (24.2 GiB आरक्षित)। |
| **32बी** (Qwen2.5-32B) | QLoRA | **उपलब्ध:** 26.0 GiB, 2048 संदर्भ में अधिकतम (27.2 GiB आरक्षित, लगभग 4 GiB अतिरिक्त)। |
| 3B | `mode="full"` (सटीक पूर्ण फाइन-ट्यूनिंग, जीपीयू पर) | **22.0 GiB** अधिकतम (संपूर्ण प्रणाली में), बैच 4 पर 0.30 सेकंड/चरण, 512 संदर्भ। इसका 7.5 GiB भाग पेज किए गए ऑप्टिमाइज़र की स्थिति है, जो छोटे कार्ड पर होस्ट रैम में फैल सकता है (अभी तक परीक्षण नहीं किया गया)। |
| **7बी-श्रेणी** (Qwen2.5-7B, 7.6 बिलियन पैरामीटर) | `mode="full" --full-ft-offload` | **ट्रेनिंग:** 5.3 GiB वीआरएएम, **30.8 GiB होस्ट रैम** (सहेजते समय 32.2 GiB), **14.7 सेकंड/चरण**। केवल लिनक्स या WSL2। |

उस सत्र में दोबारा मापा नहीं गया: 7B QLoRA, Llama-3.1-8B (सुरक्षित रिपॉजिटरी, परीक्षण मशीन पर कोई टोकन नहीं), और 3B से अधिक का पूर्ण-जीपीयू फाइन-ट्यूनिंग। दस्तावेज़ों में अन्यत्र दिए गए आंकड़े अनुमानित हैं।

अधिकांश सिंगल-जीपीयू लाइब्रेरी दो कार्यों के लिए आपको किसी अन्य स्रोत की ओर भेजती हैं: **24–32B QLoRA** और **सिंगल-कार्ड 7B-क्लास फुल फाइन-ट्यूनिंग**। बैकप्रोपैगेट इन कार्यों को एक ही उपभोक्ता कार्ड पर करता है, और फिर परिणाम को सीधे ओलामा में निर्यात कर देता है।

**पूर्ण फाइन-ट्यूनिंग के दो तरीके हैं।** ऑफलोड के बिना, मॉडल, इसके ग्रेडिएंट और ऑप्टिमाइज़र की स्थिति, ये सभी जीपीयू पर मौजूद होते हैं। लाइब्रेरी, पहचाने गए वीआरएएम के आधार पर मॉडल के आकार को सीमित करती है (**16 जीबी → 4बी, 24 जीबी → 5बी, 32 जीबी → 6बी**); ये सीमाएँ मेमोरी गणना से निर्धारित होती हैं और केवल 3बी तक मापी जाती हैं। `--full-ft-ceiling-billions` के साथ इसे बदलें।

`--full-ft-offload` होस्ट रैम में भार और ग्रेडिएंट्स को रखता है और उन्हें जीपीयू में भेजता है (FSDP2 सीपीयू ऑफलोड)। इसकी लागत, जिसे मापा गया:

- **होस्ट रैम:** यह जांच करने के लिए कहा जाता है कि क्या सिस्टम में पर्याप्त रैम है। इसके लिए लगभग 3.7 GiB प्रति अरब पैरामीटर और 10 GiB की आवश्यकता होती है, जो कि एक सुरक्षित अनुमान है (7.6 बिलियन पैरामीटर पर 39 GiB, जबकि मापा गया मान 32.2 GiB है)। यदि मशीन में पर्याप्त रैम नहीं है, तो यह प्रक्रिया शुरू करने से पहले ही रोक दी जाती है। 7.6 बिलियन पैरामीटर वाला मॉडल 28 जीबी WSL2 की मेमोरी सीमा में फिट नहीं हो सकता; व्यावहारिक रूप से, लगभग 5 बिलियन पैरामीटर की सीमा है।
- **गति:** 7.6 बिलियन पैरामीटर पर 14.7 सेकंड/चरण (बैच 1) और 3 बिलियन पैरामीटर पर 5.1 सेकंड/चरण (बैच 4), जबकि जीपीयू पर 3 बिलियन पैरामीटर के लिए लगभग 0.63 सेकंड/चरण। इसका उपयोग केवल तभी करें जब मॉडल इसके बिना फिट न हो सके। एक तेज़ संस्करण की योजना बनाई जा रही है।
- **ऑप्टिमाइज़र:** अडाफैक्टर, AdamW नहीं। भार bf16 में रहते हैं और प्रत्येक अपडेट को स्टोकास्टिक राउंडिंग के साथ वापस लिखा जाता है; कोई fp32 प्रतिलिपि नहीं है।
- **गुणवत्ता:** 3 बिलियन पैरामीटर के एक रन (150 चरण, होल्ड-आउट लॉस, एक सीड) में, इसने लगभग 85% सुधार प्राप्त किया, जो सामान्य पूर्ण फाइन-ट्यूनिंग से प्राप्त हुआ (2.45 → 1.93, जबकि 2.45 → 1.84)। एक सीड बेंचमार्क नहीं है।
- **दायरा:** साधारण पर्यवेक्षित फाइन-ट्यूनिंग। कोई पैकिंग नहीं, केवल प्रतिक्रिया मास्किंग नहीं, कोई मध्यवर्ती चेकपॉइंट नहीं, कोई फिर से शुरू नहीं। केवल लिनक्स या WSL2 (एनसीसीएल को FSDP2 की आवश्यकता है); विंडोज-नेटिव पर यह `DEP_FSDP_UNAVAILABLE` के साथ बंद हो जाता है।
- **अभी तक परीक्षण नहीं किया गया:** लंबे रन, 1 से ऊपर ग्रेडिएंट संचय, और एक भौतिक 64 जीबी मशीन (परीक्षण मशीन में अधिक रैम था, जिसमें परीक्षण द्वारा 60 GiB की सीमा लागू की गई थी)।

एक ऐसा मॉडल जो उपयुक्त नहीं है, `RUNTIME_FULL_FT_MODEL_TOO_LARGE` के साथ बाहर निकल जाता है और बाहर निकलने का तरीका बताता है। [पूर्ण फाइन-ट्यूनिंग हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/full-fine-tuning/) देखें।

### 16 जीबी तक कम किया गया

16 जीबी एनवेलप (आरटीएक्स 4080 / 5080 / 4070 टीआई सुपर) अभी भी प्रथम श्रेणी का है: 7बी QLoRA (एडेप्टर आकार को फिट करने के लिए चुना गया है: 16 जीबी कार्ड पर रैंक 64, जहां रैंक 256 को लगभग 17 जीबी की आवश्यकता होती है), और `mode="full"` के माध्यम से लगभग 3बी मॉडल का वास्तविक पूर्ण फाइन-ट्यूनिंग (SmolLM3-3B, Qwen2.5-3B, Llama-3.2-3B/1बी)। (32 जीबी कार्ड पर 3बी पर 22.0 GiB मापा गया, जिसमें से 7.5 GiB पेज किया गया ऑप्टिमाइज़र स्टेट है जो होस्ट रैम में फैल सकता है; क्या यह 16 जीबी कार्ड पर स्वीकार्य रूप से चलता है, इसका परीक्षण नहीं किया गया है)। `--full-ft-offload` के साथ, जीपीयू बहुत कम जगह लेता है: परीक्षण कार्ड पर वीआरएएम को सीमित करने पर, 6 GiB कैप और 4बी और 7.6बी मॉडल 8 GiB कैप के तहत प्रशिक्षित किए जाते हैं। ये 32 जीबी कार्ड पर अनुकरण किए गए कैप हैं, न कि वास्तविक 8 जीबी हार्डवेयर पर। समान कोड बैच आकार और सीमा चुनता है जो किसी भी कार्ड के साथ फिट बैठता है।

2-बिट क्वांटाइजेशन (एक्यूएलएम / QuIP#) **दायरे से बाहर** रहता है - 2-बिट बेस को साफ-सुथरे तरीके से पूर्ण-सटीक भार में वापस मर्ज नहीं किया जा सकता है, जो मर्ज करने योग्य-एडेप्टर → जीजीयूएफ → ओलामा निर्यात अनुबंध को तोड़ता है (पाइपलाइन का पूरा उद्देश्य)। इसके बजाय बैकप्रोपगेट हेडरूम लीवर प्रदान करता है - QLoRA, `mode="full"`, `--full-ft-offload`, और FP8 कंप्यूट पथ (`--fp8`, ब्लैकवेल/हॉपर) - ये सभी मर्ज करने योग्य और निर्यात करने योग्य रहते हैं।

## बैकप्रोपगेट किसके लिए नहीं है

यदि आपका उपयोग मामला नीचे दिया गया है, तो आप किसी अन्य लाइब्रेरी के साथ बेहतर परिणाम प्राप्त करेंगे - बैकप्रोपगेट सही विकल्प नहीं है और इसे काम करने की कोशिश करने में केवल सही उपकरण का उपयोग करने से अधिक खर्च आएगा। शुरू करने से पहले इस अनुभाग को पढ़ने से इंस्टॉलेशन-और-पुन: प्रयास चक्र से बचा जा सकता है:

- **13बी+ मॉडल का पूर्ण-पैरामीटर फाइन-ट्यूनिंग** - बैकप्रोपगेट 32 जीबी जीपीयू पर लगभग 6बी तक और `--full-ft-offload` के साथ 7बी-क्लास मॉडल का पूर्ण फाइन-ट्यून करता है ([एनवेलप](#आप-एक-जीपीयू-पर-क्या-क्या-चीजें-बारीकी-से-समायोजित-कर-सकते-हैं) देखें)। 13बी+ मॉडल का पूर्ण फाइन-ट्यून मल्टी-जीपीयू एफएसडीपी या एक बड़े कार्ड की मांग करता है। उस कंप्यूट पर खर्च करने से पहले, दोनों तरीकों से सबूतों का मूल्यांकन करें। [थिंकिंग मशीन्स 2025](https://thinkingmachines.ai/blog/lora/) रिपोर्ट करता है कि जब इसे प्रत्येक परत पर लागू किया जाता है और डेटासेट एडेप्टर की क्षमता के अनुरूप होता है, तो लगभग दो-तिहाई कंप्यूट प्रति पास के साथ, LoRA पूर्ण फाइन-ट्यूनिंग से मेल खाता है। [बिडरमैन एट अल. 2024](https://arxiv.org/abs/2405.09673) ने पाया कि मानक कम-रैंक सेटिंग्स LoRA में कोड और गणित पर पूर्ण फाइन-ट्यूनिंग की तुलना में काफी कम प्रदर्शन करते हैं, जबकि कम भूलते हैं। निर्देश-अनुसरण, व्यक्तित्व और मामूली डेटासेट पर शैली के लिए, QLoRA 32बी तक आमतौर पर एक कार्ड का बेहतर उपयोग है।
- **ऑनलाइन आरएल - पीपीओ / जीआरपीओ / आरएलवीआर** - बैकप्रोपगेट सिंगल-स्टेज एसएफटी प्लस संदर्भ-मुक्त प्राथमिकता ट्यूनिंग (ओआरपीओ v1.5 में; SimPO + केटीओ v1.6 में) करता है। यह जो नहीं करता है वह है ऑनलाइन सुदृढीकरण सीखना - पीपीओ, जीआरपीओ, या आरएलवीआर - जिसके लिए एक इनाम मॉडल या प्रशिक्षण चरण के शीर्ष पर एक पीढ़ी-और-स्कोरिंग लूप की आवश्यकता होती है। उनके लिए, सीधे टीआरएल का उपयोग करें या LLaMA-Factory। (संदर्भ-मुक्त प्राथमिकता ट्यूनिंग सिंगल-स्टेज एनवेलप के अनुरूप है क्योंकि स्मृति में रखने के लिए कोई अलग संदर्भ मॉडल नहीं है; [क्विक स्टार्ट](#त्वरित-शुरुआत) के तहत ओआरपीओ नोट देखें)।
- **मल्टी-नोड प्रशिक्षण** - केवल एक मशीन पर सिंगल जीपीयू। एक मशीन पर मल्टी-जीपीयू काम करता है (`accelerate launch` के माध्यम से) लेकिन आधिकारिक तौर पर समर्थित नहीं है।
- **CUDA रेल पर macOS प्रशिक्षण** - ऐप्पल सिलिकॉन में CUDA नहीं है, इसलिए CUDA पथ एक लिनक्स या विंडोज बॉक्स पर NVIDIA जीपीयू के साथ चलता है। आप प्रशिक्षित मॉडल को ओलामा के माध्यम से मैक पर भी चला सकते हैं। एक **प्रायोगिक, अप्रमाणित-पूर्वावलोकन** एमएलएक्स रेल (`--backend mlx`) ऐप्पल सिलिकॉन पर मूल रूप से LoRA एडेप्टर को प्रशिक्षित करता है - [एप्पल सिलिकॉन (MLX)](#एप्पल-सिलिकॉन-mlx---अप्रमाणित-पूर्वावलोकन) देखें। यह LoRA-SFT-केवल है और **वास्तविक सिलिकॉन पर डॉगफूड-प्रमाणित नहीं है** (कोई समर्थन नहीं), इसलिए LoRA एसएफटी (ओआरपीओ, पूर्ण फाइन-ट्यून, FP8, मल्टी-रन) से परे किसी भी चीज़ के लिए आप CUDA रेल चाहते हैं।
- **परीक्षण किए गए मॉडल परिवारों के बाहर कुछ भी** - क्वेन 2.5 / 3.5 (7बी / 4बी), Phi-4-mini-3.8B, SmolLM3-3B, लामा 3.2 (3बी / 1बी), मिस्ट्रल 7बी। अन्य मॉडल अक्सर काम करते हैं लेकिन सीआई में पिन नहीं किए जाते हैं।

यदि आपको इनमें से किसी भी चीज़ की आवश्यकता है, तो ऊपर सूचीबद्ध पुस्तकालयों में से किसी एक का उपयोग करें। वे इसमें बेहतर हैं।

## बैकप्रोपगेट आपको क्या देता है

एक इंस्टॉलेशन में चार चीजें:

**1. एक वास्तविक 3-पंक्ति एपीआई जो बिना कॉन्फ़िगरेशन फ़ाइल के चलता है।**
इस रीडमी के शीर्ष पर स्निपेट एंड-टू-एंड चलता है। कोई `accelerate config` नहीं, कोई वाईएएमएल नहीं, कोई हाइड्रा ओवरराइड नहीं। बस `Trainer(model).train(data)` और आपके पास एक फाइनट्यून है।

**2. विंडोज जो वास्तव में काम करता है।**
अधिकांश एमएल लाइब्रेरी विंडोज को एक विचार के रूप में मानती हैं। बैकप्रोपगेट को विंडोज 11 पर आरटीएक्स 50-श्रृंखला कार्ड के साथ विकसित और परीक्षण किया गया है। लाइब्रेरी आपके लिए रनटाइम की अजीब बातों को संभालती है - यह जानती है कि आपके डेटा को पहले से कैसे टोकन करना है ताकि विंडोज मल्टीप्रोसेसिंग क्रैश न हो, यह स्वचालित रूप से आरटीएक्स 40/50 कार्ड पर एक्सफॉर्मर्स को अक्षम कर देता है जहां यह टूट जाएगा, और यह डेटालोडर सेटिंग्स चुनता है जो विफल नहीं होती हैं। आपको इनमें से कुछ भी जानने की आवश्यकता नहीं है। यह बस चलता है।

**3. बिना निगरानी वाले रनों के लिए निर्मित।**
प्रशिक्षण में घंटों लगते हैं। आप इसकी निगरानी नहीं करना चाहते हैं। बैकप्रोपगेट को चलने के लिए छोड़ दिया जाने के लिए डिज़ाइन किया गया है:

- यदि आपके पास जीपीयू मेमोरी समाप्त हो जाती है, तो यह स्वचालित रूप से बैच आकार को आधा कर देता है और तीन बार तक पुनः प्रयास करता है। कोई हाथ से ट्यूनिंग नहीं।
- यदि आपका जीपीयू बहुत गर्म हो जाता है, तो यह तब तक रुक जाता है जब तक कि चीजें शांत न हो जाएं और फिर जारी रहती हैं।
- प्रत्येक चेकपॉइंट को परमाणु रूप से लिखा जाता है - यदि आपका लैपटॉप मध्य-सहेजते समय क्रैश हो जाता है, तो पिछला अच्छा चेकपॉइंट अभी भी बरकरार है।
- प्रत्येक प्रशिक्षण रन को एक अद्वितीय आईडी मिलती है जो प्रत्येक लॉग लाइन, प्रत्येक चेकपॉइंट और प्रत्येक वेट्स एंड बायसेस प्रविष्टि पर मुहरबंद होती है। यदि कुछ गलत हो जाता है, तो एक आईडी एक रखरखावकर्ता को सब कुछ सहसंबंधित करने देती है।
- त्रुटियां स्थिर कोड (`RUNTIME_GPU_OOM`, `DEP_OLLAMA_REGISTRATION_FAILED`, आदि) के साथ आती हैं ताकि आप अपने लॉग और [समस्या निवारण मार्गदर्शिका](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting/) में सुधार के लिए खोज कर सकें। CUDA-विशिष्ट विफलताओं के लिए एक समर्पित [CUDA समस्या निवारण पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting-cuda/) है।

**4. प्रशिक्षित एडेप्टर से `ollama run` तक एक कमांड।**
कई लाइब्रेरी एक मॉडल को प्रशिक्षित करती हैं। उनमें से कुछ ही आपको वास्तव में इसका उपयोग करने पर आपके रास्ते से हट जाते हैं। बैकप्रोपगेट एक कमांड में जीजीयूएफ (ओलामा द्वारा उपयोग किया जाने वाला प्रारूप) में निर्यात करता है और एक ओलामा मॉडल को पंजीकृत करता है। आप "प्रशिक्षण हो गया" से "मैं अपने फाइनट्यून के साथ चैट कर सकता हूं" लगभग 30 सेकंड में जाते हैं।

## त्वरित शुरुआत

कमांड लाइन से, 5-वार्तालाप उदाहरण डेटासेट के साथ:

```bash
pipx install "backpropagate[standard]"
curl -LO https://raw.githubusercontent.com/mcp-tool-shop-org/backpropagate/main/examples/quickstart.jsonl

backprop train --data quickstart.jsonl --model Qwen/Qwen2.5-7B-Instruct --steps 10
backprop generate ./output "What is Python?"      # did it learn anything?
backprop export ./output --format gguf --quantization q4_k_m --ollama --ollama-name my-first-finetune
ollama run my-first-finetune
```

`backprop train` एडेप्टर को `./output` में लिखता है (इसे `--output` से बदलें)। पायथन में, यह इस प्रकार है:

```python
from backpropagate import Trainer

trainer = Trainer("Qwen/Qwen2.5-7B-Instruct")
trainer.train("quickstart.jsonl", steps=10)
trainer.export("gguf", quantization="q4_k_m")
```

पायथन एपीआई के लिए `pip install "backpropagate[standard]"` के साथ एक वर्चुअल वातावरण का उपयोग करें; `pipx` अपने स्वयं के वातावरण में `backprop` कमांड स्थापित करता है, इसलिए `import backpropagate` इसे नहीं ढूंढ पाएगा।

**GGUF निर्यात को क्या चाहिए।** निर्यात आपके एडेप्टर को बेस मॉडल में मिलाता है और इसे llama.cpp के कनवर्टर स्क्रिप्ट के साथ परिवर्तित करता है। आपको या तो इसकी आवश्यकता है:

- एक llama.cpp **सोर्स चेकआउट** (`git clone https://github.com/ggml-org/llama.cpp ~/llama.cpp`) और उसी वातावरण में `pip install sentencepiece protobuf`, या
- अनस्लोथ, जिसमें पहले से ही इसका अपना llama.cpp निर्मित है।

`--ollama` के साथ, `q4_k_m` क्वांटाइजेशन `ollama create` द्वारा किया जाता है, इसलिए कुछ भी संकलित करने की आवश्यकता नहीं है। बैकप्रोपगेट कभी भी अनस्लोथ को आपके लिए llama.cpp बनाने के लिए सिस्टम पैकेज स्थापित करने की अनुमति नहीं देता है; यदि आप ऐसा चाहते हैं तो `BACKPROPAGATE_UNSLOTH_AUTO_INSTALL=1` सेट करें। विवरण: [निर्यात](https://mcp-tool-shop-org.github.io/backpropagate/handbook/export/)।

अपने स्वयं के डेटा के लिए, अपने JSONL को प्रति पंक्ति एक उदाहरण के रूप में स्वरूपित करें:

```jsonl
{"conversations": [{"from": "human", "value": "What is Python?"}, {"from": "gpt", "value": "A programming language."}]}
{"conversations": [{"from": "human", "value": "Explain recursion."}, {"from": "gpt", "value": "A function that calls itself."}]}
```

अल्पाका (`instruction` / `output`), OpenAI चैट (`messages`), और कच्चे पाठ प्रारूप भी काम करते हैं - बैकप्रोपगेट स्वचालित रूप से प्रारूप का पता लगाता है।

### लूप: डेटा की जाँच करें, प्रशिक्षित करें, मूल्यांकन करें, निर्यात करें

```bash
backprop data report my_data.jsonl                     # duplicates, length outliers, format problems
backprop data split my_data.jsonl --heldout-ratio 0.1  # a held-out set the model never trains on
backprop train --data my_data.train.jsonl --steps 200 --output ./run-a
backprop eval <run-id> --heldout my_data.heldout.jsonl # held-out loss + sample generations
backprop eval <run-b> --vs <run-a>                     # did the change help?
backprop export ./run-a --format gguf --ollama --ollama-name my-model
```

मूल्यांकन डिज़ाइन द्वारा न्यायाधीश-मुक्त है: होल्ड-आउट हानि प्लस नियतात्मक कार्य मीट्रिक (`normalized_exact_match`, `token_f1`, `contains`, `regex`, `pass_rate`)। एक एलएलएम न्यायाधीश का उपयोग करने के लिए, इसे `backprop generate` आउटपुट पर स्वयं चलाएं। [रेसिपी](https://mcp-tool-shop-org.github.io/backpropagate/handbook/recipes/) देखें।

### वरीयता ट्यूनिंग (ORPO, SimPO, KTO)

सादे प्रदर्शनों के बजाय प्राथमिकताओं पर प्रशिक्षित करें। ORPO संदर्भ-मुक्त और एकल-चरण है - यह वरीयता संकेत को SFT चरण में मिलाता है, इसलिए कोई अलग इनाम या संदर्भ मॉडल नहीं है और 3-पंक्ति आकार अपरिवर्तित रहता है। `--method orpo` (CLI) या `method="orpo"` (पायथन) पास करें और इसे `{prompt, chosen, rejected}` (या केवल `{chosen, rejected}`) पंक्तियों के एक डेटासेट के साथ फीड करें:

```jsonl
{"prompt": "What is Python?", "chosen": "A high-level programming language known for readability.", "rejected": "idk look it up"}
{"prompt": "Explain recursion.", "chosen": "A function that calls itself with a smaller input until a base case.", "rejected": "when something repeats"}
```

```python
from backpropagate import Trainer

trainer = Trainer("Qwen/Qwen2.5-7B-Instruct", method="orpo")
trainer.train("preferences.jsonl", steps=100)
trainer.export("gguf", quantization="q4_k_m")
```

```bash
backprop train --data preferences.jsonl --method orpo --steps 100
```

डिफ़ॉल्ट शिक्षण दर स्वचालित रूप से ORPO के लिए `8e-6` तक कम हो जाती है (हानि सादे SFT की तुलना में अधिक तेज होती है); `--orpo-beta` (डिफ़ॉल्ट `0.1`) को समायोजित करें ताकि ऑड्स-अनुपात दंड को भारित किया जा सके। ORPO केवल `mode="lora"` है।

**v1.6 में नया - SimPO और KTO।** `--method simpo` ([मेंग एट अल. 2024](https://arxiv.org/abs/2405.14734)) संदर्भ-मुक्त है जिसमें लंबाई-सामान्यीकृत इनाम होता है और यह ORPO के समान युग्मित `{prompt, chosen, rejected}` डेटा लेता है (`--simpo-beta`, `--simpo-gamma`)। `--method kto` ([एथयाराज एट अल. 2024](https://arxiv.org/abs/2402.01306)) **युग्मित नहीं** `{prompt, completion, label}` डेटा लेता है - प्रति-उदाहरण थंब्स-अप/डाउन - प्रतिक्रिया के उस बड़े वर्ग के लिए जो क्यूरेटेड A/B जोड़े नहीं हैं; यह आपके लेबल गणना से वांछनीय/अवांछनीय हानि भार को स्वचालित रूप से संतुलित करता है। दोनों केवल `mode="lora"` हैं और एकल-जीपीयू SFT लिफाफे में रहते हैं (कोई अलग संदर्भ मॉडल नहीं)। यह देखने के लिए कि किसका उपयोग करना है, [वरीयता-ट्यूनिंग हैंडबुक](https://mcp-tool-shop-org.github.io/backpropagate/handbook/preference-tuning/) देखें। ऑनलाइन आरएल (पीपीओ/जीआरपीओ) के लिए [बैकप्रोपगेट क्या नहीं है](#बैकप्रोपगेट-किसके-लिए-नहीं-है) देखें।

### तर्क-ट्रेस SFT (R1 आसवन)

एक तर्क मॉडल को आसान तरीके से आसुत करें। `--reasoning-trace` (CLI) या `Trainer(..., reasoning_trace=True)` (पायथन) पास करें और इसे ऐसे ट्रेस के साथ फीड करें जो सहायक मोड़ के अंदर `<think>...</think>` चेन-ऑफ-थॉट को बनाए रखते हैं - [DeepSeek-R1](https://arxiv.org/abs/2501.12948) आसवन का शुद्ध-SFT आधा, कोई आरएल आवश्यक नहीं है। बैकप्रोपगेट प्रशिक्षण लक्ष्य में `<think>` रखता है, खाली / बहुत लंबे ट्रेस को हटा देता है (ट्रेस-लंबाई फ़िल्टरिंग), और लंबे CoT के लिए डिफ़ॉल्ट `max_seq_length` को 8192 तक बढ़ाता है। महत्वपूर्ण रूप से, `<think>` **सादा पाठ** रहता है - कोई विशेष टोकन नहीं, कोई एम्बेडिंग आकार नहीं - इसलिए मर्ज किया गया GGUF अभी भी अन्य फाइन-ट्यून की तरह ओलामा में निर्यात करता है। केवल SFT। डेटासेट आकार और ट्यून करने योग्य टोकन बैंड के लिए [तर्क-ट्रेस रेसिपी](https://mcp-tool-shop-org.github.io/backpropagate/handbook/recipes/#reasoning-trace-sft-r1-distillation) देखें।

### एप्पल सिलिकॉन (MLX) - अप्रमाणित पूर्वावलोकन

> ⚠️ **अप्रमाणित पूर्वावलोकन - समर्थित सुविधा सेट का हिस्सा नहीं।** MLX रेल का निर्माण और इकाई परीक्षण किया गया है, लेकिन वास्तविक एप्पल सिलिकॉन पर इसे **डॉगफूड-सत्यापित नहीं** किया गया है (`mlx-lm` केवल एप्पल के लिए है और बैकप्रोपगेट जिस पर विकसित किया गया है, उस पर NVIDIA रिग पर नहीं चल सकता)। नीचे दी गई हर चीज को प्रयोगात्मक मानें, इसे अपने जोखिम पर उपयोग करें, और यदि आप इसे M-श्रृंखला मैक पर चलाते हैं तो [विसंगतियों की रिपोर्ट करें](#बग-की-रिपोर्ट-करना)।

**एक एपीआई, दो रेल।** CUDA सत्यापित, सत्यापित बैकएंड है; MLX एक दूसरी रेल है जो एप्पल के [`mlx_lm.lora`](https://github.com/ml-explore/mlx-lm) टूलचेन (एकीकृत मेमोरी, कोई CUDA नहीं) के माध्यम से M-श्रृंखला मैक पर प्रशिक्षित होती है। 3-पंक्ति आकार हार्डवेयर द्वारा रेल का चयन करता है - `backend='auto'` (डिफ़ॉल्ट) NVIDIA पर CUDA और एप्पल सिलिकॉन पर MLX पर रूट करता है, इसलिए मौजूदा CUDA रिग बाइट-समान हैं:

```python
from backpropagate import Trainer

# On an M-series Mac with `pip install 'backpropagate[mlx]'`:
trainer = Trainer("mlx-community/Qwen2.5-0.5B-Instruct-4bit", backend="mlx")
trainer.train("examples/quickstart.jsonl", steps=100)
```

```bash
backprop train --data my_data.jsonl --backend mlx --steps 100
```

MLX रेल **केवल LoRA SFT** है - कोई ORPO नहीं, कोई FP8 नहीं, कोई `mode='full'` नहीं, कोई मल्टी-रन नहीं (प्रत्येक को `CONFIG_INVALID_SETTING` के साथ अस्वीकार कर दिया जाता है; उन लोगों के लिए NVIDIA बॉक्स पर `backend='cuda'`/`'auto'` का उपयोग करें)। परिणामी एडेप्टर सादा सेफ़टेंसर है और उसी पथ के माध्यम से ओलामा में निर्यात करता है जैसे कि CUDA रेल।

> गैर-एप्पल होस्ट पर `--backend mlx` को मजबूर करने पर `CONFIG_INVALID_SETTING` त्रुटि होती है; मैक पर लापता `mlx_lm` टूलचेन `DEP_MLX_UNAVAILABLE` उत्पन्न करता है।

अधिक एंड-टू-एंड वर्कफ़्लो के लिए (फाइन-ट्यून-एंड-पुश-टू-एचएफ-हब, OOM के बाद फिर से शुरू करें, लंबे अभियान में मल्टी-रन SLAO, आदि) [हैंडबुक रेसिपी पेज](https://mcp-tool-shop-org.github.io/backpropagate/handbook/recipes/) देखें।

### वेब यूआई (वैकल्पिक)

यदि आप पायथन टाइप करने के बजाय क्लिक करना पसंद करते हैं, तो यूआई एक्स्ट्रा स्थापित करें और लॉन्च करें:

```bash
pipx install "backpropagate[ui]"
backprop ui --port 7862
```

यह जो यूआरएल प्रिंट करता है उसे खोलें, `http://127.0.0.1:7862/?token=...` (प्रत्येक लॉन्च एक नया टोकन बनाता है; पहली शुरुआत फ्रंटएंड बनाती है और इसमें एक या दो मिनट लग सकते हैं)। यह प्रशिक्षण के लिए एक स्थानीय वेब इंटरफ़ेस है: एक रन, एक मल्टी-रन स्वीप या एक निर्यात शुरू करें, इसे लाइव देखें (चरण, हानि, शेष समय, जीपीयू तापमान और मेमोरी), और इसे सहेजे गए चेकपॉइंट के साथ रोकें। प्रत्येक नौकरी अपनी प्रक्रिया में चलती है, एक समय में एक, और एक पृष्ठ रीलोड एक चल रही नौकरी को वापस उठाता है। डेटासेट पृष्ठ दिखाता है कि एक फ़ाइल में क्या है, एक साफ़ प्रति सहेजता है (दोहराव और खाली उदाहरण हटा दिए जाते हैं) और इसे प्रशिक्षण प्रपत्र में सौंपता है। पिछले रन और आपके हगिंग फेस कैश में मॉडल के अपने पृष्ठ हैं, और प्रत्येक सेटिंग में एक "i" है जो इसे समझाता है। [वेब यूआई टूर](https://mcp-tool-shop-org.github.io/backpropagate/handbook/web-ui/) प्रत्येक पृष्ठ दिखाता है। यूआई डिफ़ॉल्ट रूप से केवल स्थानीय है। इसे अन्य उपकरणों तक पहुंचाने के लिए, `--share` + `--auth` सुरक्षा अनुबंध के लिए नीचे [वेब यूआई](#वेब-यूआई) देखें।

## मल्टी-रन प्रशिक्षण

यदि आप कई डेटासेट में वृद्धिशील रूप से फाइन-ट्यून करना चाहते हैं - मान लीजिए कि आपको हर हफ्ते नया प्रशिक्षण डेटा मिलता है और आप इसे बिना पहले सीखी गई चीज़ों को भूले हुए जोड़ना चाहते हैं - तो बैकप्रोपगेट का `multi_run` मोड आपके लिए है:

```python
from backpropagate import Trainer

trainer = Trainer("Qwen/Qwen2.5-7B-Instruct")

result = trainer.multi_run(
    dataset="HuggingFaceH4/ultrachat_200k",
    num_runs=5,
    steps_per_run=100,
    samples_per_run=1000,
)
```

यह पाँच प्रशिक्षण चक्र चलाता है, और प्रत्येक चक्र के बीच एडाप्टर को इस तरह से मर्ज करता है कि पहले से मौजूद ज्ञान को संरक्षित रखा जा सके, साथ ही नए उदाहरणों को भी शामिल किया जा सके। यह तकनीक हालिया निरंतर-शिक्षण अनुसंधान पर आधारित है — इस README के नीचे [संदर्भ](#संदर्भ) देखें।

सीएलआई संस्करण:

```bash
backprop multi-run --data my_data.jsonl --runs 5 --steps 100 --samples 1000
```

## चेकपॉइंट से फिर से शुरू करें

एक 5-चक्र प्रशिक्षण जो चौथे चक्र में क्रैश हो जाता है, उसे ठीक किया जा सकता है। प्रत्येक बहु-चक्र सत्र अपनी रन आईडी को ऑन-डिस्क इतिहास और चेकपॉइंट मेनिफेस्ट में लिखता है, इसलिए जहां से आपने छोड़ा था, वहीं से शुरू करने के लिए एक कमांड है:

```bash
backprop resume <run-id>
backprop multi-run --data ... --resume <run-id>
backprop train --data ... --resume <run-id>     # single-run resume
```

`backprop multi-run` का डिफ़ॉल्ट व्यवहार (बिना `--resume` के) समान आउटपुट निर्देशिका में चल रहे प्रविष्टि का स्वतः पता लगाता है और उसे जारी रखता है। एक स्वच्छ शुरुआत के लिए, एक नई आउटपुट निर्देशिका निर्दिष्ट करें।

## प्रशिक्षण इतिहास

प्रत्येक `backprop train` और `backprop multi-run` आह्वान `<output>/run_history.json` में एक पंक्ति रिकॉर्ड करता है — उपयोग किया गया मॉडल, डेटासेट, हाइपरपैरामीटर, स्थिति, अंतिम हानि, हानि इतिहास। आप पिछले रन को सूचीबद्ध और जांच सकते हैं:

```bash
backprop list-runs                         # last 20 runs
backprop list-runs --status failed         # filter by status
backprop list-runs --json --limit 100      # machine-readable
backprop show-run abcd1234                 # detail view (partial ID is fine)
```

## प्रयोग ट्रैकिंग

बैकप्रोपैगेट स्थापित प्रयोग ट्रैकर्स (वेट्स एंड बायसेस, TensorBoard, MLflow) का स्वतः पता लगाता है और उन्हें जोड़ता है। यदि `wandb` स्थापित है और आप लॉग इन हैं, तो प्रत्येक रन स्वचालित रूप से डब्ल्यू एंड बी में एक रन नाम के साथ लॉग करता है जो ऑन-डिस्क रन आईडी से मेल खाता है — इसलिए आप डब्ल्यू एंड बी, अपने लॉग और `run_history.json` में एक पहचानकर्ता का उपयोग करके खोज कर सकते हैं।

```bash
pip install backpropagate[monitoring]   # installs wandb + psutil
wandb login                             # one-time setup
backprop train --data my_data.jsonl
```

`Trainer(report_to=["wandb"])`, `Trainer(report_to=["tensorboard"])`, या `Trainer(report_to="none")` के साथ ओवरराइड करके इसे बंद करें।

## वेब यूआई

रिफ्लेक्स वेब इंटरफ़ेस को सक्रिय करना होता है — `pipx install "backpropagate[ui]"` के साथ स्थापित करें और लॉन्च करें:

```bash
backprop ui --port 7862
```

यूआई स्थानीय रूप से चलता है: उस यूआरएल को खोलें जिसे यह प्रिंट करता है, `http://127.0.0.1:7862/?token=...`। `--auth` के बिना, प्रत्येक लॉन्च एक नया टोकन उत्पन्न करता है और यूआई उन अनुरोधों को अस्वीकार कर देता है जिनमें यह टोकन नहीं होता है। इससे आप एक डेटासेट को देख और साफ कर सकते हैं, प्रशिक्षित कर सकते हैं (एकल रन या बहु-रन), रन को लाइव देख सकते हैं, एक सहेजे गए चेकपॉइंट के साथ इसे रोक सकते हैं, और परिणाम को निर्यात कर सकते हैं। प्रत्येक कार्य अपनी प्रक्रिया में, एक समय में एक, चलता है, और यूआई को बंद करने से यह रुक जाता है। [वेब यूआई टूर](https://mcp-tool-shop-org.github.io/backpropagate/handbook/web-ui/) प्रत्येक पृष्ठ को स्क्रीनशॉट के साथ दिखाता है।

इसे अन्य उपकरणों (आपके नेटवर्क पर अन्य लोग, एक सार्वजनिक यूआरएल, आदि) तक पहुंचाने के लिए, आपको `--share` (या `--host`) को `--auth` के साथ जोड़ना होगा:

```bash
backprop ui --share --auth alice:hunter2
```

`backprop ui --share` बिना `--auth` के त्रुटि के साथ बाहर निकल जाता है। कारण: `--share` एक ऐसा यूआरएल प्रकाशित करता है जिसे इंटरनेट पर कोई भी एक्सेस कर सकता है, और प्रमाणीकरण के बिना, इसका मतलब है कि कोई भी आपके प्रशिक्षण पाइपलाइन को चला सकता है और आपके HuggingFace टोकन को पढ़ सकता है। इसके लिए कोई विकल्प नहीं है — यदि आप क्रेडेंशियल सेट नहीं करना चाहते हैं, तो इसके बजाय एसएसएच पोर्ट-फ़ॉरवर्डिंग का उपयोग करें:

```bash
# On the client:
ssh -L 7862:localhost:7862 <your-training-host>
# On the server:
backprop ui                             # no --share
# Then open the URL the server printed (http://127.0.0.1:7862/?token=...) locally
```

पूर्ण खतरे के मॉडल के लिए [हैंडबुक/सुरक्षा.एमडी](https://mcp-tool-shop-org.github.io/backpropagate/handbook/security/) देखें।

यूआई से फ़ाइल सिस्टम में की जाने वाली लेखन क्रियाएँ एक एकल निर्देशिका तक सीमित हैं:

- डिफ़ॉल्ट: `~/.backpropagate/ui-outputs`
- ओवरराइड: `BACKPROPAGATE_UI__OUTPUT_DIR=/path/you/own` सेट करें
- ओवरराइड को अस्वीकृति सूची-मान्य किया जाता है — सिस्टम या क्रेडेंशियल पथ (`/etc`, `~/.ssh`, `~/.aws`, `C:\Windows\System32`, आदि) अस्वीकार कर दिए जाते हैं

## प्लेटफ़ॉर्म नोट्स

**आवश्यकताएं:** पायथन 3.11+ · CUDA के साथ NVIDIA GPU · PyTorch 2.0+। 8 जीबी कार्ड 1बी से 3बी प्रीसेट को प्रशिक्षित करता है, 16 जीबी 7बी को, और 32 जीबी QLoRA के साथ 32बी तक।

पायथन 3.10 अब समर्थित नहीं है (जीवनकाल 2026-10-01); v1.9.0 के अनुसार न्यूनतम 3.11 है। पायथन 3.11 सबसे अधिक परीक्षण किया गया न्यूनतम संस्करण है।

बैकप्रोपैगेट विभिन्न प्लेटफ़ॉर्म पर प्रशिक्षण के दौरान आने वाली रनटाइम समस्याओं को संभालता है, लेकिन यह स्थापना-समय की समस्याओं को ठीक नहीं कर सकता है। दो सबसे आम हैं:

- **गलत CUDA व्हील।** PyTorch प्रत्येक CUDA संस्करण के लिए एक बाइनरी के रूप में प्रकाशित किया जाता है। यदि आप गलत वाला चुनते हैं, तो आपको चुपचाप केवल-सीपीयू PyTorch मिलेगा और प्रशिक्षण असंभव रूप से धीमा होगा। अपने ड्राइवर के लिए <https://pytorch.org/get-started/locally/> पर व्हील पिकर का उपयोग करें। अपना ड्राइवर / CUDA संस्करण देखने के लिए `nvidia-smi` चलाएं।
- **विंडोज + जीजीयूएफ निर्यात।** `[export]` अतिरिक्त स्रोत से `llama-cpp-python` बनाता है, जिसके लिए विज़ुअल स्टूडियो बिल्ड टूल्स (सी++ घटक) और CMake की आवश्यकता होती है।

**macOS:** CUDA रेल समर्थित नहीं है (कोई CUDA नहीं) — CUDA-आधारित `trainer.train()` `DEP_GPU_NOT_AVAILABLE` उत्पन्न करता है, और आप प्रशिक्षित एडाप्टर को ओलामा के माध्यम से मैक पर चला सकते हैं। एक **प्रायोगिक, अप्रमाणित-पूर्वावलोकन** एमएलएक्स रेल (`--backend mlx`, `pip install 'backpropagate[mlx]'`) LoRA एडाप्टर को ऐप्पल सिलिकॉन पर `mlx_lm.lora` के माध्यम से मूल रूप से प्रशिक्षित करता है — LoRA एसएफटी केवल, और **वास्तविक सिलिकॉन पर डॉगफूड-सत्यापित नहीं** (देखें [एप्पल सिलिकॉन (एमएलएक्स)](#एप्पल-सिलिकॉन-mlx---अप्रमाणित-पूर्वावलोकन))। CUDA पथ के लिए, या ORPO / पूर्ण फाइन-ट्यून / FP8 / बहु-रन के लिए, एक CUDA लिनक्स या विंडोज मशीन का उपयोग करें।

लंबी-रूप स्थापना फिक्स-इट गाइड के लिए [समस्या निवारण हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting/) देखें, और ड्राइवर / वीआरएएम / एक्सफॉर्मर्स / bf16-vs-fp16 मुद्दों के लिए समर्पित [CUDA समस्या निवारण पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting-cuda/) देखें।

## सीएलआई

प्रत्येक पायथन एपीआई का एक सीएलआई दर्पण है:

```bash
backprop train --data my_data.jsonl --model Qwen/Qwen2.5-7B-Instruct --steps 100
backprop multi-run --data my_data.jsonl --runs 5 --steps 100
backprop export ./output --format gguf --quantization q4_k_m --ollama --ollama-name my-model
backprop ui --port 7862
backprop info                          # environment + version snapshot
backprop list-runs                     # past training runs
backprop show-run <run-id>             # detail view
backprop resume <run-id>               # resume a crashed run
backprop push ./output/lora --repo me/my-model    # push adapter to HuggingFace Hub
backprop diff-runs <run-a> <run-b>     # diff two runs side by side
backprop replay <run-id>               # re-run with same config / dataset
backprop export-runs --format jsonl    # bulk export run history
```

[सीएलआई हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/cli-reference/) पर पूर्ण संदर्भ, या `backprop <subcommand> --help`।

## कॉन्फ़िगरेशन

प्रत्येक सेटिंग को `BACKPROPAGATE_` उपसर्ग का उपयोग करके एक पर्यावरण चर के साथ ओवरराइड किया जा सकता है:

| चर | डिफ़ॉल्ट | टिप्पणियाँ |
|---|---|---|
| `BACKPROPAGATE_LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `BACKPROPAGATE_LOG_JSON` | ऑटो | फोर्स जेएसओएन या कंसोल लॉग |
| `BACKPROPAGATE_MODEL__NAME` | `Qwen/Qwen2.5-7B-Instruct` | डिफ़ॉल्ट मॉडल |
| `BACKPROPAGATE_TRAINING__LEARNING_RATE` | `2e-4` | सीखने की दर |
| `BACKPROPAGATE_LORA__R` | `256` | LoRA रैंक। इसे सेट करने से स्वचालित एडाप्टर-आकार चयन बंद हो जाता है (देखें `--lora-preset` [मॉडल प्रीसेट](#मॉडल-प्रीसेट) के अंतर्गत)। |
| `BACKPROPAGATE_UI__OUTPUT_DIR` | `~/.backpropagate/ui-outputs` | यूआई फ़ाइल सिस्टम सैंडबॉक्स |

नेस्टेड कुंजियों में डबल अंडरस्कोर का उपयोग किया जाता है (`MODEL__NAME`, `MODEL_NAME` नहीं)। पूर्ण संदर्भ [पर्यावरण-चर हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/env-vars/) पर है।

## समस्या निवारण

सबसे आम पहली बार विफलताओं की एक संक्षिप्त सूची। पूरी रिवर्स इंडेक्स [समस्या निवारण हैंडबुक पेज](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting/) पर है। ड्राइवर / वीआरएएम / मिश्रित-सटीक गहन विश्लेषण के लिए [क्यूडीए समस्या निवारण पेज](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting-cuda/) देखें।

| लक्षण | त्रुटि कोड | समाधान |
|---|---|---|
| प्रशिक्षण के दौरान जीपीयू में मेमोरी समाप्त हो जाती है | `RUNTIME_GPU_OOM` | स्वचालित - बैकप्रोपगेट बैच आकार को आधा कर देता है और 3 बार तक पुनः प्रयास करता है। ऑप्ट आउट करने के लिए: `Trainer(oom_recovery=False)`। इसे छोटा करने के लिए मजबूर करने के लिए: `--batch-size 1`। |
| HuggingFace 401 / "मॉडल नहीं मिला" लौटाता है | `DEP_MODEL_LOAD_FAILED` | `huggingface-cli login` और पुनः प्रयास करें। टाइपो के लिए, <https://huggingface.co/models> से सटीक आईडी कॉपी करें। |
| `register_with_ollama` कनेक्शन अस्वीकृत | `DEP_OLLAMA_REGISTRATION_FAILED` | डेमॉन शुरू करें: `ollama serve`। <https://ollama.com> से स्थापित करें। पुनः प्रयास करने योग्य। |

| जीपीयू ज़्यादा गरम होने पर प्रशिक्षण रोक दिया गया | `RUNTIME_GPU_TEMPERATURE_CRITICAL` | स्वचालित - बैकप्रोपगेट तापमान सीमा पर रुक जाता है और जैसे ही जीपीयू ठंडा होता है, फिर से शुरू करता है। यदि यह लगातार होता रहता है तो वायु प्रवाह में सुधार करें। |
| `backprop ui --share` अस्वीकृत | `RUNTIME_UI_AUTH_NOT_ENFORCED` | `--auth user:password` पास करें, या इसके बजाय एसएसएच पोर्ट-फ़ॉरवर्डिंग का उपयोग करें (देखें [वेब यूआई](#वेब-यूआई))। |
| पहली बार में जीजीयूएफ निर्यात विफल | `RUNTIME_GGUF_EXPORT_FAILED` | `pip install backpropagate[export]`; विंडोज पर आपको विज़ुअल सी++ बिल्ड टूल्स + CMake की भी आवश्यकता है। |

## बग की रिपोर्ट करना

जब कुछ विफल हो जाता है, तो बैकप्रोपगेट स्टार्टअप पर एक पंक्ति प्रिंट करता है जैसे `run_started run_id=<uuid>` और प्रत्येक लॉग पंक्ति, प्रत्येक चेकपॉइंट और प्रत्येक वेट्स एंड बायसेस प्रविष्टि से समान आईडी को बांधता है। **किसी भी बग रिपोर्ट में `run_id` शामिल करें** - यह एक रखरखावकर्ता को उस सटीक रन के लिए सब कुछ सहसंबंधित करने देता है।

एक अच्छी बग रिपोर्ट में शामिल हैं:

1. **`run_id`** - स्टार्टअप पर मुद्रित UUID। एक UUID एक रखरखावकर्ता को उस सटीक रन के लिए प्रत्येक लॉग पंक्ति, प्रत्येक चेकपॉइंट और प्रत्येक वेट्स एंड बायसेस प्रविष्टि को सहसंबंधित करने देता है।
2. **त्रुटि कोड** - stderr में `[CODE_NAME]: message` पंक्ति। स्थिर कोड की सूची के लिए [त्रुटि कोड](https://mcp-tool-shop-org.github.io/backpropagate/handbook/error-codes/) देखें।
3. **संपादित ट्रेसबैक।** गैर-विस्तृत मोड में stderr स्वचालित रूप से संपादित किया जाता है (वाहक टोकन, `sk-*`, `hf_*`, AWS कुंजियाँ, `password=` / `token=` / `api_key=` जोड़े को हटा दिया जाता है) - पेस्ट करने के लिए सुरक्षित। पूर्ण, बिना संपादित ट्रेसबैक के लिए, `BACKPROPAGATE_DEBUG=1` (या `--verbose`) के साथ फिर से चलाएं; पोस्ट करने से पहले समीक्षा करें।
4. **`backprop info` आउटपुट।** एक कमांड पायथन / PyTorch / क्यूडीए / जीपीयू मॉडल / वीआरएएम / ओएस / स्थापित अतिरिक्त प्रिंट करता है - रखरखावकर्ता को प्लेटफ़ॉर्म-विशिष्ट प्रतिगमन को अलग करने के लिए आवश्यक सब कुछ।

[बग रिपोर्ट टेम्पलेट](https://github.com/mcp-tool-shop-org/backpropagate/issues/new?template=bug_report.yml) इनमें से प्रत्येक के लिए स्पष्ट रूप से संकेत देता है ताकि ट्राइएज तेजी से आगे बढ़े। प्रश्न, विचार, या "क्या यह अपेक्षित है?" थ्रेड [GitHub चर्चाएँ](https://github.com/mcp-tool-shop-org/backpropagate/discussions) में हैं। सुरक्षा संबंधी मुद्दों की रिपोर्ट निजी तौर पर [GitHub सुरक्षा सलाहकार](https://github.com/mcp-tool-shop-org/backpropagate/security/advisories/new) फॉर्म के माध्यम से की जानी चाहिए - नीति और प्रतिक्रिया समयरेखा के लिए [SECURITY.md](SECURITY.md) देखें।

## गोपनीयता

सभी प्रशिक्षण आपके जीपीयू पर स्थानीय रूप से होते हैं। बैकप्रोपगेट HuggingFace से मॉडल डाउनलोड करने के लिए कोई नेटवर्क अनुरोध नहीं करता है (जिसे आप शुरू करते हैं)। कोई टेलीमेट्री नहीं, कोई क्लाउड निर्भरता नहीं।

## संदर्भ

बैकप्रोपगेट की डिफ़ॉल्ट सेटिंग्स और बहु-रन प्रशिक्षण मोड हाल के शोध पर आधारित हैं। यदि आप अंतर्निहित तकनीकों में रुचि रखते हैं:

- **हु एट अल. 2021.** *LoRA: बड़े भाषा मॉडल का निम्न-श्रेणी अनुकूलन।* [arXiv:2106.09685](https://arxiv.org/abs/2106.09685) — यह मौलिक शोध पत्र है जो LoRA का परिचय देता है, जो यह बताता है कि बैकप्रोपैगेट कैसे कुशलतापूर्वक एडेप्टर को प्रशिक्षित करता है।
- **बिडरमैन एट अल. 2024.** *LoRA कम सीखता है और कम भूलता है।* [arXiv:2405.09673](https://arxiv.org/abs/2405.09673) — अनुभवजन्य प्रमाण कि 256 की श्रेणी पर सभी-रैखिक लक्ष्यों के साथ LoRA, अधिकांश पोस्ट-प्रशिक्षण कार्यों पर पूर्ण फाइन-ट्यूनिंग गुणवत्ता से 67% कंप्यूट पर मेल खाता है। यह बैकप्रोपैगेट के v1.3 डिफ़ॉल्ट LoRA कॉन्फ़िगरेशन को संचालित करता है।
- **थिंकिंग मशीन्स 2025.** *LoRA बिना किसी पछतावे के।* [thinkingmachines.ai/blog/lora](https://thinkingmachines.ai/blog/lora/) — व्यावहारिक अनुवर्ती अध्ययन जो उच्च LoRA श्रेणी पर आवश्यक 10 गुना लर्निंग-रेट-बनाम-पूर्ण-एफटी सुधार की पहचान करता है।
- **किर्कपैट्रिक एट अल. 2017.** *तंत्रिका नेटवर्क में विनाशकारी विस्मरण को दूर करना।* [arXiv:1612.00796](https://arxiv.org/abs/1612.00796) — यह मूल विशेषता है कि तंत्रिका नेटवर्क नए डेटा पर फाइन-ट्यून करते समय पहले के प्रशिक्षण को "क्यों भूल जाते हैं" (ईडब्ल्यूसी — इलास्टिक वेट कंसॉलिडेशन)।
- **वांग एट अल. 2023.** *भाषा मॉडल निरंतर सीखने के लिए ऑर्थोगोनल सबस्पेस लर्निंग।* [arXiv:2310.14152](https://arxiv.org/abs/2310.14152) — ओ-लोरा, LoRA का उपयोग करके निरंतर सीखने के लिए एक प्रारंभिक दृष्टिकोण, जिसमें नए एडेप्टर को ऑर्थोगोनल सबस्पेस तक सीमित किया जाता है।
- **यादव एट अल. 2023.** *टीआईएस-मर्जिंग: मॉडल को मर्ज करते समय हस्तक्षेप को हल करना।* [arXiv:2306.01708](https://arxiv.org/abs/2306.01708) — कई फाइन-ट्यून किए गए मॉडल को बिना किसी हस्तक्षेप के मर्ज करने के लिए एक मौलिक तकनीक।
- **कियाओ और महदावी 2025.** *भूलने से पहले मर्ज करें: निरंतर मर्जिंग के माध्यम से एक एकल LoRA निरंतर सीखना।* [arXiv:2512.23017](https://arxiv.org/abs/2512.23017) — विशिष्ट एल्गोरिदम जिसे बैकप्रोपैगेट का मल्टी-रन मर्जर लागू करता है। दिसंबर 2025 का एक प्रीप्रिंट; बैकप्रोपैगेट इस शोध पत्र का पहला ज्ञात डाउनस्ट्रीम अपनाने वाला है।
