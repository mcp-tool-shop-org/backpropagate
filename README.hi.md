# एक 32B QLoRA को या 7B एंड-टू-एंड मॉडल को एक GPU पर फाइन-ट्यून करें। इसे ओलामा में भेजें।

एक **एकल** GPU पर बड़े भाषा मॉडल को फाइन-ट्यून करें, जो आपके पास मौजूद कार्ड के आकार के अनुसार हो। तीन पंक्तियों में Python QLoRA का उपयोग करके 7B-32B मॉडल को एक 32 GB उपभोक्ता कार्ड (RTX 5090) पर फाइन-ट्यून करें। एक ध्वज, `--full-ft-offload`, 7B-क्लास मॉडल को उसके भार और ग्रेडिएंट को होस्ट RAM (Linux या WSL2 में) में रखकर पूरी तरह से फाइन-ट्यून करता है (धीमा, और नीचे मापा गया)। एक और कमांड ओलामा में निर्यात करता है, फिर `ollama run` आपके फाइन-ट्यून मॉडल को। 16 GB तक स्केल करता है। विंडोज पर उत्कृष्ट प्रदर्शन। क्या आप Python के बजाय ब्राउज़र पसंद करते हैं? `backprop ui` बिना किसी कोड के यह सब करता है ([टूर लें](https://mcp-tool-shop-org.github.io/backpropagate/handbook/web-ui/))।

```python
from backpropagate import Trainer

trainer = Trainer("Qwen/Qwen2.5-7B-Instruct")
trainer.train("my_data.jsonl", steps=100)
trainer.export("gguf", quantization="q4_k_m")
```

```bash
backprop export ./output --format gguf --quantization q4_k_m --ollama --ollama-name my-model
ollama run my-model
```

बस इतना ही। कोई YAML कॉन्फ़िगरेशन फ़ाइल नहीं है। कोई `accelerate launch` प्रक्रिया नहीं है। कोई अलग "अब इसे GGUF में बदलें" ट्यूटोरियल नहीं है। यदि आपके पास एक CUDA GPU और आपके प्रशिक्षण डेटा वाली एक JSONL फ़ाइल है, तो आप एक कार्यात्मक फाइन-ट्यून मॉडल से केवल तीन पंक्तियों की दूरी पर हैं।

## इंस्टॉल करें

```bash

pipx install backpropagate

# Or via uv (faster install, same isolation)
uv tool install backpropagate

# Standard pip (if you manage your own virtualenv)

```

यदि आप वैकल्पिक सुविधाओं को चाहते हैं, तो इंस्टॉलेशन को इनमें से किसी एक से बदलें:

```bash
pipx install "backpropagate[standard]"   # adds Unsloth (2x faster training) + the web UI
pipx install "backpropagate[full]"       # adds everything: unsloth, ui, monitoring, export, etc.
```

क्या आप डॉकर पसंद करते हैं? `docker pull ghcr.io/mcp-tool-shop-org/backpropagate:latest` भी काम करता है। `linux/amd64` और `linux/arm64` दोनों के लिए इमेज उपलब्ध हैं, इसलिए Apple Silicon और ARM Linux उपयोगकर्ताओं को एक मूल इमेज मिलेगी। "कंटेनर में UI" के लिए एक मानक `compose.yaml` रिपॉजिटरी की जड़ में स्थित है: `user:password` को `ui-auth.txt` में रखें, `docker compose up` चलाएं, और `http://127.0.0.1:7860` पर साइन इन करें (पहली बार शुरू करने पर फ्रंटएंड बनाया जाता है, जिसमें एक या दो मिनट लगते हैं)। रन इतिहास `~/.backpropagate` में बना रहता है।

## बैकप्रोपगेट कहाँ स्थित है

LLM को फाइन-ट्यून करने के लिए कई अच्छे लाइब्रेरी उपलब्ध हैं। वे प्रत्येक अलग-अलग चीजों में उत्कृष्ट हैं:

- **[Axolotl](https://github.com/OpenAccess-AI-Collective/axolotl)** — यदि आप YAML कॉन्फ़िगरेशन पसंद करते हैं और आपको कॉपी करने के लिए व्यंजनों का एक समुदाय चाहिए।
- **[LLaMA-Factory](https://github.com/hiyouga/LLaMA-Factory)** — यदि आप DPO/PPO/RLHF और एक वेब GUI चाहते हैं।
- **[Unsloth](https://github.com/unslothai/unsloth)** — यदि आपको सबसे तेज़ प्रशिक्षण की आवश्यकता है और आप समर्थित मॉडल परिवार पर हैं।
- **[torchtune](https://github.com/pytorch/torchtune)** — यदि आप मेटा के पहले-पक्षीय PyTorch-नेटिव व्यंजनों को संपादित करना चाहते हैं।

बैकप्रोपगेट वह विकल्प है जो गायब था: **एक एकल उपभोक्ता GPU पर अकेले ऑपरेटरों के लिए 3-पंक्ति Python API जो एक एडाप्टर को प्रशिक्षित करना और उसे भेजना चाहते हैं। कोई YAML नहीं, कोई ऑनलाइन RL (PPO/GRPO) नहीं, कोई मल्टी-नोड नहीं। यदि आप कोड नहीं लिखना चाहते हैं, तो उसी लूप के लिए एक ब्राउज़र UI भी उपलब्ध है। केवल वही लूप जिसकी हर किसी को वास्तव में आवश्यकता है और वह निर्यात चरण जो बाधा डालता है।

यदि आपने ऊपर दिए गए लाइब्रेरी में से किसी एक को आज़माया और कॉन्फ़िगरेशन-फ़ाइल प्रक्रिया से निराश हो गए, या मॉडल-परिवार की कमी का सामना किया, या विंडोज-प्रथम डिफ़ॉल्ट चाहते हैं - तो बैकप्रोपगेट आपके लिए है।

## आप एक GPU पर क्या फाइन-ट्यून कर सकते हैं

बैकप्रोपगेट आपके कार्ड के अनुसार रन को आकार देता है। ये 32 GB RTX 5090 पर **मापे गए** आंकड़े हैं: 2026-10-03 के QLoRA पंक्तियाँ (रसीदें: [`docs/receipts/2026-10-03-presets/`](docs/receipts/2026-10-03-presets/)), 2026-09-30 की पूर्ण फाइन-ट्यूनिंग पंक्तियाँ (रसीदें: [`docs/receipts/2026-09-30-offload/`](docs/receipts/2026-09-30-offload/))। QLoRA चरम मान पूर्वनिर्धारित की पूर्ण संदर्भ विंडो पर बैच 1 के साथ होते हैं, जो उस पूर्वनिर्धारित के लिए सबसे खराब स्थिति है; छोटे उदाहरण कम उपयोग करते हैं।

| मॉडल | विधि | 32 GB कार्ड पर मापा गया |
|---|---|---|
| **14B** (Qwen2.5-14B) | QLoRA | **18.7 GiB** 4096 संदर्भ पर चरम (20.0 GiB आरक्षित)। |
| 24B (Mistral-Small-24B) | QLoRA | 22.8 GiB 4096 संदर्भ पर चरम (24.2 GiB आरक्षित)। |
| **32B** (Qwen2.5-32B) | QLoRA | **फिट बैठता है:** 2048 संदर्भ पर 26.0 GiB चरम (27.2 GiB आरक्षित, लगभग 4 GiB अतिरिक्त)। |
| 3B | `mode="full"` (सच्चा पूर्ण फाइन-ट्यूनिंग, GPU पर) | **22.0 GiB** चरम (सिस्टम-व्यापी), 0.30 s/चरण बैच 4, 512 संदर्भ पर। इसका 7.5 GiB पेज किया गया ऑप्टिमाइज़र स्थिति है, जो छोटे कार्ड पर होस्ट RAM में फैल सकता है (अपरिक्षित)। |
| **7B-क्लास** (Qwen2.5-7B, 7.6B पैरामीटर) | `mode="full" --full-ft-offload` | **प्रशिक्षित:** 5.3 GiB VRAM, **30.8 GiB होस्ट RAM** (32.2 GiB सहेजते समय), **14.7 s/चरण**। केवल Linux या WSL2। |

उस सत्र में फिर से नहीं मापा गया: 7B QLoRA, Llama-3.1-8B (गेटेड रिपॉजिटरी, परीक्षण मशीन पर कोई टोकन नहीं), और 3B से ऊपर का शुद्ध-GPU पूर्ण फाइन-ट्यूनिंग। उन आंकड़ों के लिए दस्तावेज़ों में अन्यत्र अनुमान दिए गए हैं।

दो चीजें जिनके लिए अधिकांश एकल-GPU लाइब्रेरी आपको कहीं और भेजती हैं, **24-32B QLoRA** और **एकल-कार्ड 7B-क्लास पूर्ण फाइन-ट्यूनिंग**, बैकप्रोपगेट एक उपभोक्ता कार्ड पर करता है, फिर परिणाम को सीधे ओलामा में निर्यात करता है।

**पूर्ण फाइन-ट्यूनिंग के दो मार्ग हैं।** ऑफलोड के बिना, मॉडल, इसके ग्रेडिएंट और ऑप्टिमाइज़र स्थिति सभी GPU पर होते हैं। लाइब्रेरी पता लगाए गए VRAM द्वारा मॉडल आकार को सीमित करती है (**16 GB → 4B, 24 GB → 5B, 32 GB → 6B**); ये सीमाएँ मेमोरी गणना से आती हैं और केवल 3B तक मापी जाती हैं। `--full-ft-ceiling-billions` के साथ ओवरराइड करें।

`--full-ft-offload` भार और ग्रेडिएंट को होस्ट RAM में रखता है और उन्हें GPU पर स्ट्रीम करता है (FSDP2 CPU ऑफलोड)। यह क्या खर्च करता है, मापा गया:

- **होस्ट रैम:** फिट चेक में लगभग 3.7 गीबी प्रति अरब पैरामीटर और 10 गीबी की आवश्यकता होती है, जो कि रूढ़िवादी है (7.6बी पर 39 गीबी बनाम मापे गए 32.2 गीबी)। यदि मशीन में पर्याप्त मेमोरी नहीं है, तो शुरुआत में ही रन को अस्वीकार कर दिया जाता है। 7.6बी मॉडल 28 जीबी डब्ल्यूएसएल2 मेमोरी सीमा के भीतर फिट नहीं होता है; लगभग 5बी वहां व्यावहारिक सीमा है।
- **गति:** 7.6बी पर 14.7 एस/स्टेप (बैच 1) और 3बी पर 5.1 एस/स्टेप (बैच 4), बैच 4 पर जीपीयू पर 3बी के लिए लगभग 0.63 एस/स्टेप। इसका उपयोग केवल तभी करें जब मॉडल इसके बिना फिट न हो। एक तेज़ संस्करण की योजना बनाई जा रही है।
- **ऑप्टिमाइज़र:** एडाफैक्टर, एडमडब्ल्यू नहीं। वेट bf16 में रहते हैं और प्रत्येक अपडेट को स्टोकास्टिक राउंडिंग के साथ वापस लिखा जाता है; कोई fp32 कॉपी नहीं है।
- **गुणवत्ता:** एक 3बी रन (150 स्टेप, होल्ड-आउट लॉस, एक सीड) पर, इसने लगभग 85% सुधार प्राप्त किया जो सामान्य पूर्ण फाइन-ट्यूनिंग से प्राप्त हुआ (2.45 → 1.93 बनाम 2.45 → 1.84)। एक सीड बेंचमार्क नहीं है।
- **दायरा:** साधारण पर्यवेक्षित फाइन-ट्यूनिंग। कोई पैकिंग नहीं, केवल प्रतिक्रिया मास्किंग नहीं, कोई मध्यवर्ती चेकपॉइंट नहीं, कोई फिर से शुरू नहीं। केवल लिनक्स या डब्ल्यूएसएल2 (एफएसडीपी2 को एनसीसीएल की आवश्यकता है); विंडोज-नेटिव पर यह `DEP_FSDP_UNAVAILABLE` के साथ बंद हो जाता है।
- **अभी तक परीक्षण नहीं किया गया:** लंबे रन, 1 से ऊपर ग्रेडिएंट संचय, और एक भौतिक 64 जीबी मशीन (परीक्षण मशीन में अधिक रैम थी, जिसमें परीक्षण द्वारा 60 गीबी की सीमा लागू की गई थी)।

एक मॉडल जो फिट नहीं होता है, वह `RUNTIME_FULL_FT_MODEL_TOO_LARGE` के साथ बाहर निकल जाता है और बाहर निकलने का तरीका बताता है। [पूर्ण फाइन-ट्यूनिंग हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/full-fine-tuning/) देखें।

### 16 जीबी तक स्केल डाउन होता है

16 जीबी एनवेलप (आरटीएक्स 4080 / 5080 / 4070 टीआई सुपर) अभी भी प्रथम श्रेणी का है: 7बी क्यूएलओआरए (एडेप्टर आकार को फिट करने के लिए चुना जाता है: 16 जीबी कार्ड पर रैंक 64, जहां रैंक 256 को लगभग 17 जीबी की आवश्यकता होती है), और लगभग 3बी मॉडल (स्मोलएलएम3-3बी, क्वेन2.5-3बी, लामा-3.2-3बी/1बी) का वास्तविक पूर्ण फाइन-ट्यूनिंग `mode="full"` के माध्यम से। (32 जीबी कार्ड पर 3बी पर 22.0 गीबी मापा गया, जिसमें से 7.5 गीबी पेज्ड ऑप्टिमाइज़र स्थिति है जो होस्ट रैम में फैल सकती है; क्या यह 16 जीबी कार्ड पर स्वीकार्य रूप से चलता है, इसका परीक्षण नहीं किया गया है)। `--full-ft-offload` के साथ, जीपीयू बहुत कम मेमोरी रखता है: परीक्षण कार्ड पर वीआरएएम सीमित होने पर, 6 गीबी की सीमा के तहत प्रशिक्षित 3बी मॉडल और 8 गीबी की सीमा के तहत 4बी और 7.6बी मॉडल। ये 32 जीबी कार्ड पर अनुकरण किए गए कैप हैं, वास्तविक 8 जीबी हार्डवेयर पर नहीं। समान कोड बैच आकार और छत को चुनता है जो भी कार्ड फिट बैठता है।

2-बिट क्वांटाइजेशन (एक्यूएलएम / क्वआईपी#) **दायरे से बाहर** रहता है - 2-बिट बेस को साफ-सुथरे तरीके से पूर्ण-सटीक वेट में वापस मर्ज नहीं किया जा सकता है, जो मर्ज करने योग्य-एडेप्टर → जीजीयूएफ → ओलामा निर्यात अनुबंध को तोड़ता है (पाइपलाइन का पूरा बिंदु)। इसके बजाय बैकप्रोपगेट में हेड रूम लीवर होते हैं - क्यूएलओआरए, `mode="full"`, `--full-ft-offload`, और एफपी8 कंप्यूट पथ (`--fp8`, ब्लैकवेल/हॉपर) - ये सभी मर्ज करने योग्य और निर्यात करने योग्य रहते हैं।

## बैकप्रोपगेट किसके लिए नहीं है

यदि आपका उपयोग मामला नीचे दिया गया है, तो आप किसी अन्य लाइब्रेरी के साथ बेहतर प्रदर्शन करेंगे - बैकप्रोपगेट सही विकल्प नहीं है और इसे काम करने के लिए मजबूर करने से केवल सही उपकरण तक पहुंचने से अधिक खर्च आएगा। शुरू करने से पहले इस अनुभाग को पढ़ने से इंस्टॉलेशन-और-बाउंस चक्र से बचा जा सकता है:

- **13बी+ मॉडल का पूर्ण-पैरामीटर फाइन-ट्यूनिंग** - बैकप्रोपगेट 32 जीबी जीपीयू पर लगभग 6बी तक और `--full-ft-offload` के साथ 7बी-क्लास मॉडल का पूर्ण-फाइन-ट्यून करता है (देखें [एनवेलप](#आप-एक-जीपीयू-पर-क्या-फाइन-ट्यून-कर-सकते-हैं))। 13बी+ मॉडल का पूर्ण फाइन-ट्यून मल्टी-जीपीयू एफएसडीपी या एक बड़े कार्ड को चाहता है। उस कंप्यूट पर खर्च करने से पहले, दोनों तरीकों से सबूतों का मूल्यांकन करें। [थिंकिंग मशीन्स 2025](https://thinkingmachines.ai/blog/lora/) रिपोर्ट करता है कि जब इसे प्रत्येक परत पर लागू किया जाता है और डेटासेट एडेप्टर की क्षमता में फिट बैठता है, तो एलओआरए पूर्ण फाइन-ट्यूनिंग से मेल खाता है, प्रति पास लगभग दो-तिहाई कंप्यूट पर। [बिडरमैन एट अल. 2024](https://arxiv.org/abs/2405.09673) ने पाया कि मानक कम-रैंक सेटिंग्स में एलओआरए कोड और गणित पर पूर्ण फाइन-ट्यूनिंग से काफी कम प्रदर्शन करता है, जबकि कम भूलता है। निर्देश-अनुसरण, व्यक्तित्व और मामूली डेटासेट पर शैली के लिए, 32बी तक क्यूएलओआरए आमतौर पर एक कार्ड का बेहतर उपयोग है।
- **ऑनलाइन आरएल - पीपीओ / जीआरपीओ / आरएलवीआर** - बैकप्रोपगेट सिंगल-स्टेज एसएफटी प्लस संदर्भ-मुक्त प्राथमिकता ट्यूनिंग करता है (v1.5 में ओआरपीओ; v1.6 में सिम्पो + केटीओ)। यह जो नहीं करता है वह है ऑनलाइन सुदृढीकरण सीखना - पीपीओ, जीआरपीओ, या आरएलवीआर - जिसके लिए एक इनाम मॉडल या प्रशिक्षण चरण के शीर्ष पर एक पीढ़ी-और-स्कोरिंग लूप की आवश्यकता होती है। उनके लिए, सीधे टीआरएल या एलएलएएमए-फैक्ट्री का उपयोग करें। (संदर्भ-मुक्त प्राथमिकता ट्यूनिंग सिंगल-स्टेज एनवेलप में फिट बैठता है क्योंकि मेमोरी में रखने के लिए कोई अलग संदर्भ मॉडल नहीं है; [क्विक स्टार्ट](#क्विक-स्टार्ट) के तहत ओआरपीओ नोट देखें)।
- **मल्टी-नोड प्रशिक्षण** - केवल एक मशीन पर एक जीपीयू। एक मशीन पर मल्टी-जीपीयू काम करता है (`accelerate launch` के माध्यम से) लेकिन आधिकारिक तौर पर समर्थित नहीं है।
- **सीयूडीए रेल पर मैकओएस प्रशिक्षण** - ऐप्पल सिलिकॉन में सीयूडीए नहीं है, इसलिए सीयूडीए पथ एनवीडिया जीपीयू के साथ लिनक्स या विंडोज बॉक्स पर चलता है। आप प्रशिक्षित मॉडल को ओलामा के माध्यम से मैक पर भी चला सकते हैं। एक **प्रायोगिक, अप्रमाणित-पूर्वावलोकन** एमएलएक्स रेल (`--backend mlx`) ऐप्पल सिलिकॉन पर मूल रूप से एक एलओआरए एडेप्टर को प्रशिक्षित करता है - [एप्पल सिलिकॉन (एमएलएक्स)](#एप्पल-सिलिकॉन-एमएलएक्स--अप्रमाणित-पूर्वावलोकन) देखें। यह केवल एलओआरए-एसएफटी है और **वास्तविक सिलिकॉन पर डॉगफूड-प्रमाणित नहीं है** (कोई समर्थन नहीं), इसलिए एलओआरए एसएफटी (ओआरपीओ, पूर्ण फाइन-ट्यून, एफपी8, मल्टी-रन) से परे किसी भी चीज़ के लिए आप सीयूडीए रेल चाहते हैं।
- **परीक्षण किए गए मॉडल परिवारों के बाहर कुछ भी** - क्वेन 2.5 / 3.5 (7बी / 4बी), फी-4-मिनी-3.8बी, स्मोलएलएम3-3बी, लामा 3.2 (3बी / 1बी), मिस्ट्रल 7बी। अन्य मॉडल अक्सर काम करते हैं लेकिन सीआई में पिन नहीं किए जाते हैं।

यदि आपको इनमें से किसी भी चीज़ की आवश्यकता है, तो ऊपर सूचीबद्ध पुस्तकालयों में से किसी एक का उपयोग करें। वे इसमें बेहतर हैं।

## बैकप्रोपगेट आपको क्या देता है

एक इंस्टॉलेशन में चार चीजें:

**1. एक वास्तविक 3-पंक्ति एपीआई जो बिना कॉन्फ़िगरेशन फ़ाइल के चलता है।**
इस रीडमी के शीर्ष पर स्निपेट एंड-टू-एंड चलता है। कोई `accelerate config` नहीं, कोई वाईएएमएल नहीं, कोई हाइड्रा ओवरराइड नहीं। बस `Trainer(model).train(data)` और आपके पास एक फाइनट्यून है।

**2. विंडोज जो वास्तव में काम करता है।**
अधिकांश एमएल लाइब्रेरी विंडोज को एक बाद में सोचा जाने वाला विचार मानती हैं। बैकप्रोपगेट को विंडोज 11 पर आरटीएक्स 50-सीरीज़ कार्ड के साथ विकसित और परीक्षण किया गया है। लाइब्रेरी आपके लिए रनटाइम की विशिष्टताओं को संभालती है - यह जानती है कि आपके डेटा को पहले से कैसे टोकनाइज़ करना है ताकि विंडोज मल्टीप्रोसेसिंग क्रैश न हो, यह स्वचालित रूप से आरटीएक्स 40/50 कार्ड पर एक्सफॉर्मर्स को अक्षम कर देती है जहां यह समस्या पैदा कर सकता है, और यह डेटा लोडर सेटिंग्स चुनती है जो समस्या नहीं पैदा करती हैं। आपको इनमें से किसी भी चीज़ को जानने की आवश्यकता नहीं है। यह बस चलता है।

**3. बिना निगरानी के चलने के लिए बनाया गया।**
प्रशिक्षण में घंटों लगते हैं। आप इसे लगातार देखते नहीं रहना चाहते। बैकप्रोपगेट को इस तरह से डिज़ाइन किया गया है कि इसे चालू छोड़ दिया जाए:

- यदि आपके पास जीपीयू मेमोरी कम हो जाती है, तो यह स्वचालित रूप से बैच आकार को आधा कर देता है और फिर से प्रयास करता है - अधिकतम तीन बार। कोई मैन्युअल ट्यूनिंग नहीं।
- यदि आपका जीपीयू बहुत गर्म हो जाता है, तो यह तब तक रुक जाता है जब तक कि चीजें शांत न हो जाएं और फिर जारी रहता है।
- प्रत्येक चेकपॉइंट को परमाणु रूप से लिखा जाता है - यदि आपका लैपटॉप बचत के बीच में क्रैश हो जाता है, तो भी पिछला अच्छा चेकपॉइंट बरकरार रहता है।
- प्रत्येक प्रशिक्षण रन को एक अद्वितीय आईडी मिलती है जो प्रत्येक लॉग लाइन, प्रत्येक चेकपॉइंट और प्रत्येक वेट्स और बायसेस प्रविष्टि पर अंकित होती है। यदि कुछ गलत होता है, तो एक आईडी रखरखावकर्ता को सब कुछ सहसंबंधित करने की अनुमति देती है।
- त्रुटियां स्थिर कोड (`RUNTIME_GPU_OOM`, `DEP_OLLAMA_REGISTRATION_FAILED`, आदि) के साथ आती हैं ताकि आप अपने लॉग को देख सकें और [समस्या निवारण मार्गदर्शिका](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting/) में समाधान ढूंढ सकें। CUDA-विशिष्ट विफलताओं के लिए एक समर्पित [CUDA समस्या निवारण पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting-cuda/) है।

**4. प्रशिक्षित एडाप्टर से `ollama run` तक एक कमांड।**
कई लाइब्रेरी एक मॉडल को प्रशिक्षित करती हैं। उनमें से कुछ ही तब आपके रास्ते से हटती हैं जब आप वास्तव में इसका उपयोग करना चाहते हैं। बैकप्रोपगेट GGUF (वह प्रारूप जिसका उपयोग ओलामा करता है) में निर्यात करता है और एक कमांड में एक ओलामा मॉडल को पंजीकृत करता है। आप "प्रशिक्षण पूरा हुआ" से "मैं अपने फाइनट्यून के साथ चैट कर सकता हूं" तक लगभग 30 सेकंड में पहुंच जाते हैं।

## त्वरित शुरुआत

कमांड लाइन से, 5-वार्तालाप उदाहरण डेटासेट के साथ:

```bash
pipx install "backpropagate[standard]"
curl -LO https://raw.githubusercontent.com/mcp-tool-shop-org/backpropagate/main/examples/quickstart.jsonl

backprop train --data quickstart.jsonl --model Qwen/Qwen2.5-7B-Instruct --steps 10
backprop generate ./output "What is Python?"      # did it learn anything?
backprop export ./output --format gguf --quantization q4_k_m --ollama --ollama-name my-first-finetune
ollama run my-first-finetune
```

`backprop train` एडाप्टर को `./output` में लिखता है (इसे `--output` से बदलें)। पायथन में, वही चीज़ इस प्रकार है:

```python
from backpropagate import Trainer

trainer = Trainer("Qwen/Qwen2.5-7B-Instruct")
trainer.train("quickstart.jsonl", steps=10)
trainer.export("gguf", quantization="q4_k_m")
```

पायथन एपीआई के लिए `pip install "backpropagate[standard]"` के साथ एक वर्चुअल वातावरण का उपयोग करें; `pipx` अपने स्वयं के वातावरण में `backprop` कमांड स्थापित करता है, इसलिए `import backpropagate` इसे नहीं ढूंढ पाएगा।

**GGUF निर्यात को क्या चाहिए।** निर्यात आपके एडाप्टर को बेस मॉडल में मर्ज करता है और इसे लामा.cpp के कनवर्टर स्क्रिप्ट के साथ परिवर्तित करता है। आपको या तो:

- लामा.cpp **सोर्स चेकआउट** (`git clone https://github.com/ggml-org/llama.cpp ~/llama.cpp`) और उसी वातावरण में `pip install sentencepiece protobuf`, या
- अनस्लोथ, जिसमें पहले से ही इसका अपना लामा.cpp निर्मित है।

`--ollama` के साथ, `q4_k_m` क्वांटाइजेशन `ollama create` द्वारा किया जाता है, इसलिए कुछ भी संकलित करने की आवश्यकता नहीं है। बैकप्रोपगेट कभी भी अनस्लोथ को लामा.cpp बनाने के लिए सिस्टम पैकेज स्थापित करने की अनुमति नहीं देता है; यदि आप ऐसा चाहते हैं तो `BACKPROPAGATE_UNSLOTH_AUTO_INSTALL=1` सेट करें। विवरण: [निर्यात](https://mcp-tool-shop-org.github.io/backpropagate/handbook/export/)।

अपने स्वयं के डेटा के लिए, अपने JSONL को प्रति पंक्ति एक उदाहरण के रूप में स्वरूपित करें:

```jsonl
{"conversations": [{"from": "human", "value": "What is Python?"}, {"from": "gpt", "value": "A programming language."}]}
{"conversations": [{"from": "human", "value": "Explain recursion."}, {"from": "gpt", "value": "A function that calls itself."}]}
```

अल्पाका (`instruction` / `output`), ओपनएआई चैट (`messages`), और कच्चे पाठ प्रारूप भी काम करते हैं - बैकप्रोपगेट स्वचालित रूप से प्रारूप का पता लगाता है।

### लूप: डेटा की जांच करें, प्रशिक्षित करें, मूल्यांकन करें, निर्यात करें

```bash
backprop data report my_data.jsonl                     # duplicates, length outliers, format problems
backprop data split my_data.jsonl --heldout-ratio 0.1  # a held-out set the model never trains on
backprop train --data my_data.train.jsonl --steps 200 --output ./run-a
backprop eval <run-id> --heldout my_data.heldout.jsonl # held-out loss + sample generations
backprop eval <run-b> --vs <run-a>                     # did the change help?
backprop export ./run-a --format gguf --ollama --ollama-name my-model
```

मूल्यांकन डिज़ाइन द्वारा बिना किसी जज के होता है: होल्ड-आउट हानि प्लस नियतात्मक कार्य मीट्रिक (`normalized_exact_match`, `token_f1`, `contains`, `regex`, `pass_rate`)। एलएलएम जज का उपयोग करने के लिए, इसे `backprop generate` आउटपुट पर स्वयं चलाएं। [रेसिपी](https://mcp-tool-shop-org.github.io/backpropagate/handbook/recipes/) देखें।

### वरीयता ट्यूनिंग (ORPO, SimPO, KTO)

सादे प्रदर्शनों के बजाय प्राथमिकताओं पर प्रशिक्षित करें। ORPO संदर्भ-मुक्त और एकल-चरण है - यह वरीयता संकेत को एसएफटी चरण में जोड़ता है, इसलिए कोई अलग इनाम या संदर्भ मॉडल नहीं है और 3-पंक्ति आकार अपरिवर्तित रहता है। `--method orpo` (सीएलआई) या `method="orpo"` (पायथन) पास करें और `{prompt, chosen, rejected}` (या केवल `{chosen, rejected}`) पंक्तियों के एक डेटासेट को फीड करें:

```jsonl
{"prompt": "What is Python?", "chosen": "A high-level programming language known for readability.", "rejected": "idk look it up"}
{"prompt": "Explain recursion.", "chosen": "A function that calls itself with a smaller input until a base case.", "rejected": "when something repeats"}
```

```python
from backpropagate import Trainer

trainer = Trainer("Qwen/Qwen2.5-7B-Instruct", method="orpo")
trainer.train("preferences.jsonl", steps=100)
trainer.export("gguf", quantization="q4_k_m")
```

```bash
backprop train --data preferences.jsonl --method orpo --steps 100
```

डिफ़ॉल्ट शिक्षण दर स्वचालित रूप से ORPO के लिए `8e-6` तक कम हो जाती है (हानि सादे एसएफटी की तुलना में अधिक तेज होती है); `--orpo-beta` (डिफ़ॉल्ट `0.1`) को समायोजित करें ताकि ऑड्स-अनुपात दंड को भार दिया जा सके। ORPO केवल `mode="lora"` है।

**v1.6 में नया - SimPO और KTO।** `--method simpo` ([मेंग एट अल. 2024](https://arxiv.org/abs/2405.14734)) एक लंबाई-सामान्यीकृत इनाम के साथ संदर्भ-मुक्त है और ORPO के समान युग्मित `{prompt, chosen, rejected}` डेटा लेता है (`--simpo-beta`, `--simpo-gamma`)। `--method kto` ([एथयाराज एट अल. 2024](https://arxiv.org/abs/2402.01306)) **अयुग्मित** `{prompt, completion, label}` डेटा लेता है - प्रति-उदाहरण थम्स-अप/डाउन - प्रतिक्रिया के उस बड़े वर्ग के लिए जो क्यूरेटेड ए/बी जोड़े नहीं हैं; यह वांछनीय/अवांछनीय हानि भार को आपके लेबल गणना से स्वचालित रूप से संतुलित करता है। दोनों केवल `mode="lora"` हैं और एकल-जीपीयू एसएफटी लिफाफे में रहते हैं (कोई अलग संदर्भ मॉडल नहीं)। उपयोग करने के लिए [वरीयता-ट्यूनिंग हैंडबुक](https://mcp-tool-shop-org.github.io/backpropagate/handbook/preference-tuning/) देखें। ऑनलाइन आरएल (पीपीओ/जीआरपीओ) के लिए [बैकप्रोपगेट क्या नहीं है](#what-backpropagate-is-not-for) देखें।

### तर्क-ट्रेस एसएफटी (आर1 आसवन)

एक तर्क मॉडल को आसानी से आसवित करें। `--reasoning-trace` (सीएलआई) या `Trainer(..., reasoning_trace=True)` (पायथन) पास करें और ऐसे ट्रेस फीड करें जो सहायक मोड़ के अंदर `<think>...</think>` श्रृंखला-की-विचार श्रृंखला को बनाए रखें - [डीपसीक-आर1](https://arxiv.org/abs/2501.12948) आसवन का शुद्ध-एसएफटी आधा, कोई आरएल आवश्यक नहीं है। बैकप्रोपगेट `<think>` को प्रशिक्षण लक्ष्य में रखता है, खाली / बहुत लंबे ट्रेस को छोड़ देता है (ट्रेस-लंबाई फ़िल्टरिंग), और लंबे CoT के लिए डिफ़ॉल्ट `max_seq_length` को 8192 तक बढ़ाता है। महत्वपूर्ण रूप से, `<think>` **सादा पाठ** रहता है - कोई विशेष टोकन नहीं, कोई एम्बेडिंग आकार परिवर्तन नहीं - इसलिए मर्ज किया गया जीजीयूएफ अभी भी ओलामा में किसी अन्य फाइन-ट्यून की तरह निर्यात करता है। केवल एसएफटी। डेटासेट आकार और ट्यून करने योग्य टोकन बैंड के लिए [तर्क-ट्रेस रेसिपी](https://mcp-tool-shop-org.github.io/backpropagate/handbook/recipes/#reasoning-trace-sft-r1-distillation) देखें।

### एप्पल सिलिकॉन (एमएलएक्स) - अप्रमाणित पूर्वावलोकन

> ⚠️ **अपुष्ट पूर्वावलोकन — समर्थित सुविधाओं के सेट का हिस्सा नहीं।** MLX रेल का निर्माण और इकाई परीक्षण किया गया है, लेकिन इसे वास्तविक Apple सिलिकॉन पर "डॉगफूड-सत्यापित" नहीं किया गया है (`mlx-lm` केवल Apple के लिए है और NVIDIA रिग पर नहीं चल सकता, जिस पर बैकप्रोपगेट विकसित किया गया है)। नीचे दी गई हर चीज़ को प्रयोगात्मक मानें, इसे अपने जोखिम पर उपयोग करें, और यदि आप इसे M-सीरीज़ मैक पर चलाते हैं तो [विसंगतियों की रिपोर्ट करें](#reporting-bugs)।

**एक API, दो रेल।** CUDA मान्य, सत्यापित बैकएंड है; MLX एक दूसरी रेल है जो Apple के [`mlx_lm.lora`](https://github.com/ml-explore/mlx-lm) टूलचेन (एकीकृत मेमोरी, CUDA नहीं) के माध्यम से M-सीरीज़ मैक पर प्रशिक्षित होती है। 3-पंक्ति आकार हार्डवेयर के आधार पर रेल का चयन करता है — `backend='auto'` (डिफ़ॉल्ट) NVIDIA पर CUDA और Apple सिलिकॉन पर MLX पर रूट करता है, इसलिए मौजूदा CUDA रिग बाइट-दर-बाइट समान हैं:

```python
from backpropagate import Trainer

# On an M-series Mac with `pip install 'backpropagate[mlx]'`:
trainer = Trainer("mlx-community/Qwen2.5-0.5B-Instruct-4bit", backend="mlx")
trainer.train("examples/quickstart.jsonl", steps=100)
```

```bash
backprop train --data my_data.jsonl --backend mlx --steps 100
```

MLX रेल **केवल LoRA SFT** है — कोई ORPO नहीं, कोई FP8 नहीं, कोई `mode='full'` नहीं, कोई मल्टी-रन नहीं (प्रत्येक को `CONFIG_INVALID_SETTING` के साथ अस्वीकार किया जाता है; NVIDIA बॉक्स पर उन कार्यों के लिए `backend='cuda'`/`'auto'` का उपयोग करें)। परिणामी एडाप्टर सादा सेफ़टेंसर है और CUDA रेल के समान पथ के माध्यम से ओलामा में निर्यात करता है।

> गैर-Apple होस्ट पर `--backend mlx` को जबरदस्ती लागू करने पर `CONFIG_INVALID_SETTING` त्रुटि आती है; मैक पर लापता `mlx_lm` टूलचेन `DEP_MLX_UNAVAILABLE` उत्पन्न करता है।

अधिक एंड-टू-एंड वर्कफ़्लो (फाइन-ट्यून-एंड-पुश-टू-HF-हब, OOM के बाद फिर से शुरू करें, लंबे अभियान में मल्टी-रन SLAO, आदि) के लिए [हैंडबुक रेसिपी पेज](https://mcp-tool-shop-org.github.io/backpropagate/handbook/recipes/) देखें।

### वेब UI (वैकल्पिक)

यदि आप पायथन टाइप करने के बजाय क्लिक करना पसंद करते हैं, तो UI एक्स्ट्रा स्थापित करें और लॉन्च करें:

```bash
pipx install "backpropagate[ui]"
backprop ui --port 7862
```

उस URL को खोलें जो यह प्रिंट करता है, `http://127.0.0.1:7862/?token=...` (प्रत्येक लॉन्च एक नया टोकन बनाता है; पहली शुरुआत फ्रंटएंड बनाता है और इसमें एक या दो मिनट लग सकते हैं)। यह प्रशिक्षण के लिए एक स्थानीय वेब इंटरफ़ेस है: एक रन, एक मल्टी-रन स्वीप या एक निर्यात शुरू करें, इसे लाइव देखें (चरण, हानि, शेष समय, GPU तापमान और मेमोरी), और इसे सहेजे गए चेकपॉइंट के साथ रोकें। प्रत्येक कार्य अपने स्वयं के प्रक्रिया में, एक समय में एक, चलता है, और एक पृष्ठ रीलोड चल रहे कार्य को फिर से शुरू करता है। डेटासेट पृष्ठ दिखाता है कि किसी फ़ाइल में क्या है, एक साफ़ प्रति सहेजता है (दोहराव और खाली उदाहरण हटा दिए जाते हैं) और इसे प्रशिक्षण प्रपत्र में भेजता है। पिछले रन और आपके Hugging Face कैश में मॉडल के अपने पृष्ठ हैं, और प्रत्येक सेटिंग में एक "i" है जो इसे समझाता है। [वेब UI टूर](https://mcp-tool-shop-org.github.io/backpropagate/handbook/web-ui/) प्रत्येक पृष्ठ दिखाता है। डिफ़ॉल्ट रूप से UI केवल स्थानीय है। इसे अन्य उपकरणों तक विस्तारित करने के लिए, नीचे [वेब UI](#web-ui) में `--share` + `--auth` सुरक्षा अनुबंध देखें।

## मल्टी-रन प्रशिक्षण

यदि आप कई डेटासेट में वृद्धिशील रूप से फाइन-ट्यून करना चाहते हैं — मान लीजिए कि आपको हर हफ्ते नया प्रशिक्षण डेटा मिलता है और आप इसे पहले से सीखे गए ज्ञान को भूले बिना जोड़ना चाहते हैं — तो बैकप्रोपगेट का `multi_run` मोड आपके लिए है:

```python
from backpropagate import Trainer

trainer = Trainer("Qwen/Qwen2.5-7B-Instruct")

result = trainer.multi_run(
    dataset="HuggingFaceH4/ultrachat_200k",
    num_runs=5,
    steps_per_run=100,
    samples_per_run=1000,
)
```

यह पाँच प्रशिक्षण पास चलाता है, रन के बीच एडाप्टर को इस तरह मर्ज करता है कि पहले के ज्ञान को संरक्षित किया जा सके, जबकि नए उदाहरणों को शामिल किया जा सके। यह तकनीक हाल के निरंतर-शिक्षण अनुसंधान पर आधारित है — इस README के नीचे [संदर्भ](#references) देखें।

CLI संस्करण:

```bash
backprop multi-run --data my_data.jsonl --runs 5 --steps 100 --samples 1000
```

## चेकपॉइंट से फिर से शुरू करें

रन 4 पर क्रैश होने वाला 5-रन प्रशिक्षण पुनर्प्राप्त करने योग्य है। प्रत्येक मल्टी-रन सत्र अपने रन ID को ऑन-डिस्क इतिहास और चेकपॉइंट मेनिफेस्ट में लिखता है, इसलिए जहां आपने छोड़ा था, वहां से शुरू करना एक कमांड है:

```bash
backprop resume <run-id>
backprop multi-run --data ... --resume <run-id>
backprop train --data ... --resume <run-id>     # single-run resume
```

`backprop multi-run` (बिना `--resume` के) का डिफ़ॉल्ट व्यवहार उसी आउटपुट निर्देशिका में एक प्रगति पर प्रविष्टि का स्वतः पता लगाता है और उसे जारी रखता है। एक स्वच्छ शुरुआत को मजबूर करने के लिए, एक ताज़ा आउटपुट निर्देशिका पर इंगित करें।

## प्रशिक्षण इतिहास

प्रत्येक `backprop train` और `backprop multi-run` आह्वान `<output>/run_history.json` में एक पंक्ति रिकॉर्ड करता है — उपयोग किया गया मॉडल, डेटासेट, हाइपरपैरामीटर, स्थिति, अंतिम हानि, हानि इतिहास। आप पिछले रन को सूचीबद्ध और निरीक्षण कर सकते हैं:

```bash
backprop list-runs                         # last 20 runs
backprop list-runs --status failed         # filter by status
backprop list-runs --json --limit 100      # machine-readable
backprop show-run abcd1234                 # detail view (partial ID is fine)
```

## प्रयोग ट्रैकिंग

बैकप्रोपगेट स्थापित प्रयोग ट्रैकर्स (वेट्स एंड बायसेस, टेंसरबोर्ड, MLflow) का स्वतः पता लगाता है और उन्हें जोड़ता है। यदि `wandb` स्थापित है और आप लॉग इन हैं, तो प्रत्येक रन स्वचालित रूप से W&B में एक रन नाम के साथ लॉग करता है जो ऑन-डिस्क रन ID से मेल खाता है — इसलिए आप W&B, अपने लॉग और `run_history.json` में एक पहचानकर्ता का उपयोग करके खोज कर सकते हैं।

```bash
pip install backpropagate[monitoring]   # installs wandb + psutil
wandb login                             # one-time setup
backprop train --data my_data.jsonl
```

`Trainer(report_to=["wandb"])`, `Trainer(report_to=["tensorboard"])` या `Trainer(report_to="none")` के साथ ओवरराइड करें।

## वेब UI

रिफ्लेक्स वेब इंटरफ़ेस वैकल्पिक है — `pipx install "backpropagate[ui]"` के साथ स्थापित करें और लॉन्च करें:

```bash
backprop ui --port 7862
```

UI स्थानीय रूप से चलता है: उस URL को खोलें जो यह प्रिंट करता है, `http://127.0.0.1:7862/?token=...`। `--auth` के बिना, प्रत्येक लॉन्च एक नया टोकन उत्पन्न करता है और UI उन अनुरोधों को अस्वीकार कर देता है जिनमें यह नहीं है। इससे आप एक डेटासेट को देख और साफ़ कर सकते हैं, प्रशिक्षित कर सकते हैं (एकल रन या मल्टी-रन), रन को लाइव देख सकते हैं, इसे सहेजे गए चेकपॉइंट के साथ रोक सकते हैं और परिणाम को निर्यात कर सकते हैं। प्रत्येक कार्य अपने स्वयं के प्रक्रिया में, एक समय में एक, चलता है, और UI को बंद करने से यह रुक जाता है। [वेब UI टूर](https://mcp-tool-shop-org.github.io/backpropagate/handbook/web-ui/) स्क्रीनशॉट के साथ प्रत्येक पृष्ठ को दिखाता है।

इसे अन्य उपकरणों तक विस्तारित करने के लिए (आपके नेटवर्क पर अन्य लोग, एक सार्वजनिक URL, आदि), आपको `--share` (या `--host`) को `--auth` के साथ जोड़ना होगा:

```bash
backprop ui --share --auth alice:hunter2
```

`backprop ui --share` बिना `--auth` के त्रुटि के साथ बाहर निकल जाता है। कारण: `--share` एक URL प्रकाशित करता है जिसे इंटरनेट पर कोई भी एक्सेस कर सकता है, और प्रमाणीकरण के बिना इसका मतलब है कि कोई भी आपके प्रशिक्षण पाइपलाइन को चला सकता है और आपके HuggingFace टोकन को पढ़ सकता है। इसके लिए कोई विकल्प नहीं है — यदि आप क्रेडेंशियल सेट नहीं करना चाहते हैं, तो इसके बजाय SSH पोर्ट-फ़ॉरवर्डिंग का उपयोग करें:

```bash
# On the client:
ssh -L 7862:localhost:7862 <your-training-host>
# On the server:
backprop ui                             # no --share
# Then open the URL the server printed (http://127.0.0.1:7862/?token=...) locally
```

संपूर्ण खतरे के मॉडल के लिए [हैंडबुक/सुरक्षा.md](https://mcp-tool-shop-org.github.io/backpropagate/handbook/security/) देखें।

UI से फ़ाइल सिस्टम लेखन को एक एकल निर्देशिका तक सीमित किया गया है:

- डिफ़ॉल्ट: `~/.backpropagate/ui-outputs`
- ओवरराइड: `BACKPROPAGATE_UI__OUTPUT_DIR=/path/you/own` सेट करें
- ओवरराइड को अस्वीकार सूची-मान्य किया जाता है — सिस्टम या क्रेडेंशियल पथ (`/etc`, `~/.ssh`, `~/.aws`, `C:\Windows\System32`, आदि) अस्वीकार कर दिए जाते हैं

## प्लेटफ़ॉर्म नोट्स

**आवश्यकताएं:** पायथन 3.10+ · CUDA के साथ NVIDIA GPU · PyTorch 2.0+। 8 GB कार्ड 1B से 3B प्रीसेट को प्रशिक्षित करता है, 16 GB 7B को, और 32 GB QLoRA के साथ 32B तक।

पायथन 3.10 को कम से कम v1.6 तक समर्थित किया जाता है; यह अक्टूबर 2026 में अपस्ट्रीम जीवनचक्र के अंत तक पहुंचेगा और उसके बाद पहले रिलीज़ में इसे हटाने का कार्यक्रम है। नए इंस्टॉलेशन के लिए, पायथन 3.11 या 3.12 को प्राथमिकता दें - 3.11 सबसे अधिक परीक्षण किया गया संस्करण है।

बैकप्रोपैगेट विभिन्न प्लेटफ़ॉर्म पर प्रशिक्षण के दौरान आने वाली रनटाइम संबंधी समस्याओं को संभालता है, लेकिन यह इंस्टॉलेशन के समय आने वाली समस्याओं को ठीक नहीं कर सकता। दो सबसे आम समस्याएं हैं:

- **गलत CUDA व्हील।** PyTorch प्रत्येक CUDA संस्करण के लिए एक बाइनरी प्रकाशित करता है। यदि आप गलत संस्करण चुनते हैं, तो आपको चुपचाप केवल CPU-आधारित PyTorch मिलेगा और प्रशिक्षण असंभव रूप से धीमा होगा। अपने ड्राइवर के लिए <https://pytorch.org/get-started/locally/> पर व्हील पिकर का उपयोग करें। अपना ड्राइवर / CUDA संस्करण देखने के लिए `nvidia-smi` चलाएं।
- **विंडोज + GGUF निर्यात।** `[export]` अतिरिक्त बिल्ड `llama-cpp-python` को स्रोत से बनाता है, जिसके लिए विज़ुअल स्टूडियो बिल्ड टूल्स (C++ घटक) और CMake की आवश्यकता होती है।

**macOS:** CUDA समर्थित नहीं है (कोई CUDA नहीं) - CUDA-आधारित `trainer.train()` `DEP_GPU_NOT_AVAILABLE` त्रुटि उत्पन्न करेगा, और आप प्रशिक्षित एडाप्टर को Ollama के माध्यम से मैक पर चला सकते हैं। एक **प्रायोगिक, अप्रमाणित-पूर्वावलोकन** MLX रेल (`--backend mlx`, `pip install 'backpropagate[mlx]'`) `mlx_lm.lora` के माध्यम से Apple Silicon पर मूल रूप से एक LoRA एडाप्टर को प्रशिक्षित करता है - केवल LoRA SFT, और **वास्तविक सिलिकॉन पर डॉगफूड-प्रमाणित नहीं** (देखें [Apple Silicon (MLX)](#apple-silicon-mlx--unverified-preview))। CUDA पथ के लिए, या ORPO / पूर्ण फाइन-ट्यून / FP8 / मल्टी-रन के लिए, एक CUDA लिनक्स या विंडोज मशीन का उपयोग करें।

विस्तृत इंस्टॉलेशन फिक्स-इट गाइड के लिए [समस्या निवारण हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting/) देखें, और ड्राइवर / VRAM / xformers / bf16-vs-fp16 मुद्दों के लिए समर्पित [CUDA समस्या निवारण पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting-cuda/) देखें।

## CLI

प्रत्येक पायथन API का एक CLI मिरर है:

```bash
backprop train --data my_data.jsonl --model Qwen/Qwen2.5-7B-Instruct --steps 100
backprop multi-run --data my_data.jsonl --runs 5 --steps 100
backprop export ./output --format gguf --quantization q4_k_m --ollama --ollama-name my-model
backprop ui --port 7862
backprop info                          # environment + version snapshot
backprop list-runs                     # past training runs
backprop show-run <run-id>             # detail view
backprop resume <run-id>               # resume a crashed run
backprop push ./output/lora --repo me/my-model    # push adapter to HuggingFace Hub
backprop diff-runs <run-a> <run-b>     # diff two runs side by side
backprop replay <run-id>               # re-run with same config / dataset
backprop export-runs --format jsonl    # bulk export run history
```

[CLI हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/cli-reference/) पर पूर्ण संदर्भ, या `backprop <subcommand> --help`।

## कॉन्फ़िगरेशन

प्रत्येक सेटिंग को `BACKPROPAGATE_` उपसर्ग का उपयोग करके एक पर्यावरण चर के साथ ओवरराइड किया जा सकता है:

| चर | डिफ़ॉल्ट | टिप्पणियाँ |
|---|---|---|
| `BACKPROPAGATE_LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `BACKPROPAGATE_LOG_JSON` | ऑटो | JSON या कंसोल लॉग को बाध्य करें |
| `BACKPROPAGATE_MODEL__NAME` | `Qwen/Qwen2.5-7B-Instruct` | डिफ़ॉल्ट मॉडल |
| `BACKPROPAGATE_TRAINING__LEARNING_RATE` | `2e-4` | सीखने की दर |
| `BACKPROPAGATE_LORA__R` | `256` | LoRA रैंक। इसे सेट करने से स्वचालित एडाप्टर-आकार चयन बंद हो जाता है (देखें [मॉडल प्रीसेट](#model-presets) के अंतर्गत `--lora-preset`)। |
| `BACKPROPAGATE_UI__OUTPUT_DIR` | `~/.backpropagate/ui-outputs` | UI फ़ाइलसिस्टम सैंडबॉक्स |

नेस्टेड कुंजियों में डबल अंडरस्कोर का उपयोग करें (`MODEL__NAME`, `MODEL_NAME` नहीं)। पूर्ण संदर्भ [env-vars हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/env-vars/) पर है।

## समस्या निवारण

सबसे आम पहली-रन विफलताओं का एक संक्षिप्त सूचकांक। पूर्ण रिवर्स इंडेक्स [समस्या निवारण हैंडबुक पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting/) पर है। ड्राइवर / VRAM / मिश्रित-सटीक गहन-डाइव के लिए [CUDA समस्या निवारण पृष्ठ](https://mcp-tool-shop-org.github.io/backpropagate/handbook/troubleshooting-cuda/) देखें।

| लक्षण | त्रुटि कोड | समाधान |
|---|---|---|
| प्रशिक्षण के दौरान GPU में मेमोरी कम हो गई | `RUNTIME_GPU_OOM` | स्वचालित — बैकप्रोपैगेट बैच आकार को आधा कर देता है और 3 बार तक पुनः प्रयास करता है। इसे बंद करने के लिए: `Trainer(oom_recovery=False)`। इसे छोटा करने के लिए: `--batch-size 1`। |
| हगिंगफेस 401 / "मॉडल नहीं मिला" लौटाता है | `DEP_MODEL_LOAD_FAILED` | `huggingface-cli login` और पुनः प्रयास करें। टाइपो के लिए, <https://huggingface.co/models> से सटीक आईडी कॉपी करें। |
| `register_with_ollama` कनेक्शन अस्वीकृत | `DEP_OLLAMA_REGISTRATION_FAILED` | डेमॉन शुरू करें: `ollama serve`। <https://ollama.com> से स्थापित करें। पुनः प्रयास किया जा सकता है। |
| चेकपॉइंट सहेजते समय डिस्क भर गई | `STATE_CHECKPOINT_INVALID` | एटॉमिक राइट्स क्रैश होने पर `.partial` निर्देशिका छोड़ देते हैं — इसे सुरक्षित रूप से हटाया जा सकता है। पिछली अच्छी चेकपॉइंट बरकरार है। |
| GPU के ज़्यादा गरम होने पर प्रशिक्षण रोक दिया गया | `RUNTIME_GPU_TEMPERATURE_CRITICAL` | स्वचालित — बैकप्रोपैगेट तापमान सीमा पर रुक जाता है और जैसे ही GPU ठंडा होता है, फिर से शुरू हो जाता है। यदि यह बार-बार होता है, तो वायु प्रवाह में सुधार करें। |
| `backprop ui --share` अस्वीकृत | `RUNTIME_UI_AUTH_NOT_ENFORCED` | `--auth user:password` पास करें, या इसके बजाय SSH पोर्ट-फ़ॉरवर्डिंग का उपयोग करें (देखें [वेब यूआई](#web-ui))। |
| पहली बार में GGUF निर्यात विफल | `RUNTIME_GGUF_EXPORT_FAILED` | `pip install backpropagate[export]`; विंडोज पर आपको विज़ुअल सी++ बिल्ड टूल्स + CMake की भी आवश्यकता होगी। |

## बग की रिपोर्ट करना

जब कुछ विफल हो जाता है, तो बैकप्रोपैगेट स्टार्टअप पर एक पंक्ति प्रिंट करता है, जैसे `run_started run_id=<uuid>`, और प्रत्येक लॉग पंक्ति, प्रत्येक चेकपॉइंट और प्रत्येक वेट्स एंड बायसेस प्रविष्टि से समान आईडी को जोड़ता है। **किसी भी बग रिपोर्ट में `run_id` शामिल करें** — इससे एक रखरखावकर्ता उस विशिष्ट रन के लिए सब कुछ सहसंबंधित कर सकता है।

एक अच्छी बग रिपोर्ट में शामिल हैं:

1. **`run_id`** — स्टार्टअप पर मुद्रित UUID। एक UUID एक रखरखावकर्ता को उस विशिष्ट रन के लिए प्रत्येक लॉग पंक्ति, प्रत्येक चेकपॉइंट और प्रत्येक वेट्स एंड बायसेस प्रविष्टि को सहसंबंधित करने देता है।
2. **त्रुटि कोड** — stderr में `[CODE_NAME]: message` पंक्ति। स्थिर कोड की सूची के लिए [त्रुटि कोड](https://mcp-tool-shop-org.github.io/backpropagate/handbook/error-codes/) देखें।
3. **संपादित ट्रेसबैक।** गैर-विस्तृत मोड में stderr को स्वचालित रूप से संपादित किया जाता है (बियरर टोकन, `sk-*`, `hf_*`, AWS कुंजियाँ, `password=` / `token=` / `api_key=` जोड़े को हटा दिया जाता है) — इसे सुरक्षित रूप से पेस्ट किया जा सकता है। पूर्ण, बिना संपादित ट्रेसबैक के लिए, `BACKPROPAGATE_DEBUG=1` (या `--verbose`) के साथ फिर से चलाएं; पोस्ट करने से पहले समीक्षा करें।
4. **`backprop info` आउटपुट।** एक कमांड पायथन / पायटॉर्च / CUDA / GPU मॉडल / VRAM / OS / स्थापित अतिरिक्त — सब कुछ प्रिंट करता है जिसकी रखरखावकर्ता को प्लेटफ़ॉर्म-विशिष्ट प्रतिगमन को अलग करने के लिए आवश्यकता होती है।

[बग रिपोर्ट टेम्पलेट](https://github.com/mcp-tool-shop-org/backpropagate/issues/new?template=bug_report.yml) इनमें से प्रत्येक के लिए स्पष्ट रूप से संकेत देता है ताकि ट्राइएज तेजी से आगे बढ़े। प्रश्न, विचार, या "क्या यह अपेक्षित है?" थ्रेड [गिटहब डिस्कशन](https://github.com/mcp-tool-shop-org/backpropagate/discussions) में होने चाहिए। सुरक्षा संबंधी मुद्दों की निजी तौर पर [गिटहब सुरक्षा सलाहकार](https://github.com/mcp-tool-shop-org/backpropagate/security/advisories/new) फॉर्म के माध्यम से रिपोर्ट की जानी चाहिए — नीति और प्रतिक्रिया समय-सीमा के लिए [SECURITY.md](SECURITY.md) देखें।

## गोपनीयता

सभी प्रशिक्षण आपके GPU पर स्थानीय रूप से होते हैं। बैकप्रोपैगेट हगिंगफेस से मॉडल डाउनलोड करने के अलावा कोई नेटवर्क अनुरोध नहीं करता है (जिसे आप शुरू करते हैं)। कोई टेलीमेट्री नहीं, कोई क्लाउड निर्भरता नहीं।

## संदर्भ

बैकप्रोपैगेट की डिफ़ॉल्ट सेटिंग्स और मल्टी-रन प्रशिक्षण मोड हालिया शोध पर आधारित हैं। यदि आप अंतर्निहित तकनीकों में रुचि रखते हैं:

- **हु एट अल. 2021।** *LoRA: बड़े भाषा मॉडल का कम-रैंक अनुकूलन।* [arXiv:2106.09685](https://arxiv.org/abs/2106.09685) — यह मूलभूत पेपर LoRA का परिचय देता है, जो बैकप्रोपैगेट को एडेप्टर को कुशलतापूर्वक प्रशिक्षित करने में मदद करता है।
- **बिडरमैन एट अल. 2024।** *LoRA कम सीखता है और कम भूलता है।* [arXiv:2405.09673](https://arxiv.org/abs/2405.09673) — अनुभवजन्य प्रमाण कि रैंक 256 पर सभी-रैखिक लक्ष्यों के साथ LoRA, अधिकांश पोस्ट-प्रशिक्षण कार्यों पर 67% कंप्यूट पर पूर्ण फाइन-ट्यूनिंग गुणवत्ता से मेल खाता है। बैकप्रोपैगेट के v1.3 डिफ़ॉल्ट LoRA कॉन्फ़िगरेशन को चलाता है।
- **थिंकिंग मशीन 2025।** *LoRA बिना पछतावे के।* [thinkingmachines.ai/blog/lora](https://thinkingmachines.ai/blog/lora/) — व्यावहारिक अनुवर्ती जो उच्च LoRA रैंक पर आवश्यक 10× लर्निंग-रेट-बनाम-पूर्ण-एफटी सुधार की पहचान करता है।
- **किर्कपैट्रिक एट अल. 2017।** *तंत्रिका नेटवर्क में विनाशकारी विस्मरण को दूर करना।* [arXiv:1612.00796](https://arxiv.org/abs/1612.00796) — तंत्रिका नेटवर्क के "भूलने" के मूल कारण का वर्णन, जब आप नए डेटा पर फाइन-ट्यून करते हैं (EWC — इलास्टिक वेट कंसॉलिडेशन)।
- **वांग एट अल. 2023।** *भाषा मॉडल निरंतर सीखने के लिए ऑर्थोगोनल सबस्पेस लर्निंग।* [arXiv:2310.14152](https://arxiv.org/abs/2310.14152) — O-LoRA, LoRA का उपयोग करके निरंतर सीखने के लिए एक प्रारंभिक दृष्टिकोण, नए एडेप्टर को ऑर्थोगोनल सबस्पेस तक सीमित करके।
- **यादव एट अल. 2023।** *TIES-मर्जिंग: मॉडल को मर्ज करते समय हस्तक्षेप को हल करना।* [arXiv:2306.01708](https://arxiv.org/abs/2306.01708) — कई फाइन-ट्यून किए गए मॉडल को हस्तक्षेप के बिना मर्ज करने के लिए एक मूलभूत तकनीक।
- **कियाओ और महदावी 2025।** *भूलने से पहले मर्ज करें: निरंतर मर्जिंग के माध्यम से एक एकल LoRA निरंतर सीखना।* [arXiv:2512.23017](https://arxiv.org/abs/2512.23017) — विशिष्ट एल्गोरिदम जिसे बैकप्रोपैगेट का मल्टी-रन मर्जर लागू करता है। दिसंबर 2025 का एक प्रीप्रिंट; बैकप्रोपैगेट पेपर का पहला ज्ञात डाउनस्ट्रीम अपनाने वाला है।
