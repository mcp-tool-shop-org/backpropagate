# `backprop ui` start-up and auth: end-to-end check, 2026-10-01

Test record, not public documentation. Branch `fix/ui-startup-and-auth-e2e`, based on
`fix/ui-auth-hardening` (`ad13076`). Rig: Windows 11, Python 3.12.13, Reflex 0.9.3 (installed;
`uv.lock` pins 0.9.5), granian 2.7.5, node v22.22.3, CPU only (nothing here touches the GPU).
The worktree runs against `PYTHONPATH=<worktree>` so the subprocess imports the code under test.

## 1. The defect, reproduced

```
cd <worktree>; $env:PYTHONPATH=<worktree>; $env:PYTHONIOENCODING='utf-8'
E:/AI/backpropagate/.venv/Scripts/python.exe -m backpropagate ui --port 7962
```

The frontend comes up on 7962, the backend never does:

```
File ".../reflex/utils/exec.py", line 519, in get_reload_paths
    raise RuntimeError(msg)
RuntimeError: There should not be an `__init__.py` file in your app root directory
```

`get_reload_paths()` walks up from the app module (`backpropagate/ui_app/app.py`), reaches
`backpropagate/` (non-empty `__init__.py`, holds `rxconfig.py`, is the cwd) and raises. Only the
dev backends call it (`run_uvicorn_backend`, `run_granian_backend`); the check is identical in
Reflex 0.9.3, 0.9.5 and 0.9.12 (read from `reflex/utils/exec.py` at tags v0.9.5 and v0.9.12 with
`gh api repos/reflex-dev/reflex/contents/reflex/utils/exec.py?ref=<tag>`). `_run_prod` ->
`run_backend_prod` never calls it in any of the three.

## 2. Options measured

| | Option 1: `reflex run --env prod`, one port | Option 2: dev mode, app root Reflex accepts |
|---|---|---|
| Layout | unchanged (`cwd=backpropagate/`) | temp root with `rxconfig.py` + `ui_app/__init__.py` (empty) + `ui_app/app.py` shim; hot reload watches only that root |
| Backend starts | yes | yes (59 s first start in a fresh root) |
| Listeners | `127.0.0.1:7962` only | `0.0.0.0:7962` + `[::]:7962` (Vite), `127.0.0.1:7963` (backend) |
| `GET http://127.0.0.1:7962/` | 401 (middleware) | 200, no auth at all |
| `GET /?token=<tok>` on the user-facing port | 302 + `Set-Cookie` | 200, no cookie: the request never reaches the middleware |
| `GET :7963/?token=<tok>` | n/a (one port) | 302 + `Set-Cookie` (the only place the token works) |
| First start (no `.web`, warm bun cache) | 43.9 s via the CLI | 59.4 s |
| Cached start | 17-22 s | not measured |
| `--share` tunnel target | the guarded port | the unguarded Vite port |

Option 1 chosen: it fixes the start-up, puts the middleware in front of every byte (the compiled
frontend is mounted into the backend ASGI app before the `api_transformer` chain is applied, in
0.9.3, 0.9.5 and 0.9.12), removes the 0.0.0.0 Vite listener, and answers the "does `?token=` on N
reach the middleware" question by making N the only port. Option 2 only fixes the first symptom.
`.web` build output stays in the package directory as before.

A second defect surfaced as soon as prod mode was tried: the production build's prerender died with
`ReferenceError: rawColorMode is not defined`. `theme=rx.theme(appearance=rx.color_mode, ...)`
compiles (Reflex 0.9.3 / 0.9.5) to `export const defaultColorMode = rawColorMode` in
`.web/utils/context.js`, and `rawColorMode` is only defined inside the provider component. Dev mode
would hit the same line in the browser. Fixed with `appearance="inherit"` (Radix follows the
light/dark class Reflex writes on `<html>`); 0.9.12 tolerates the old form, "inherit" is correct on
all versions.

## 3. End-to-end results (real UI, real sockets)

Server: `python -m backpropagate ui --port 7962` (default) and `... --auth alice:<random>`;
`curl.exe` for HTTP; a raw-socket WebSocket handshake for `/_event` (`GET /_event/?EIO=4&transport=websocket`
with `Upgrade`, `Origin: http://127.0.0.1:7962`). Token and cookie values are not recorded.

### Default mode (token)

| # | Request | Result |
|---|---|---|
| 1 | `GET /` | 401, `www-authenticate: Basic realm="backpropagate"` |
| 2 | `GET /?token=wrong` | 401 |
| 3 | `GET /?token=<banner token>` | 302, `location: /`, `set-cookie: backprop_sess=...; Path=/; HttpOnly; SameSite=Lax; Max-Age=43200` |
| 4 | `GET /` with only `Cookie: backprop_sess=...` | 200 (real app HTML) |
| 5 | `GET /assets/<compiled>.js` without / with the cookie | 401 / 200 (static frontend is behind the middleware too) |
| 6 | `GET /` with `Host: evil.example` (also with the valid `?token=`) | 421 / 421 |
| 7 | WebSocket `/_event`, no cookie | 403 (closed before accept) |
| 8 | WebSocket `/_event`, valid cookie | 101 Switching Protocols |
| 9 | WebSocket `/_event`, valid cookie, `Origin: http://evil.example` | 403 |
| 10 | WebSocket `/_event`, `&token=<tok>` in the query, no cookie | refused (the token is a page credential; only the cookie opens the socket) |
| 11 | WebSocket, valid cookie, `Host: evil.example` | refused |
| 12 | Listeners | one: `127.0.0.1:7962` (7963 closed) |
| 13 | Lock file `session-7962.lock` while running | exists; content equals the banner token |
| 14 | Reflex child tree environment | `BACKPROPAGATE_UI_LAUNCH_TOKEN`, `_PORT`, `_HOST_BIND` present; no `BACKPROPAGATE_UI_AUTH` |
| 15 | Ctrl+C (CTRL_BREAK mapped to `KeyboardInterrupt`) | exit 0, `UI stopped`, lock file deleted, 1.4-1.9 s, no process or listener left |

Browser check (Browser pane, `http://127.0.0.1:7962/?token=...` from the banner): redirected to `/`,
"backpropagate · train" rendered, `<html class="dark">`, console shows `Socket is reconnected`
(WebSocket up), cookie not readable from JavaScript (HttpOnly). One console error, unrelated to this
change: the CSP (`style-src 'self' 'unsafe-inline'`) blocks the Google Fonts stylesheet.

### `--auth alice:<random>` mode

| # | Request | Result |
|---|---|---|
| 1 | `GET /` no credentials | 401 + `www-authenticate: Basic realm="backpropagate"` |
| 2 | `GET /` wrong password / wrong user | 401 / 401 |
| 3 | `GET /?token=<anything>` | 401 (no launch token in this mode) |
| 4 | `GET /` right password (Basic) | 200 + session cookie |
| 5 | `GET /` cookie only | 200 |
| 6 | `GET /` right password, `Host: evil.example` | 421 |
| 7 | WebSocket no cookie / Basic header only / cookie | 403 / refused / 101 |
| 8 | Lock file | none written |
| 9 | Reflex child tree (env and command line, checked with psutil, only booleans asserted) | no plaintext password; `BACKPROPAGATE_UI_AUTH_USER` + `BACKPROPAGATE_UI_AUTH_VERIFIER` (`scrypt$...`) present and `verify_password(<password>, verifier)` is true |
| 10 | CLI stdout/stderr, lock dir | no password |
| 11 | Ctrl+C | exit 0, nothing left running |

Note: the CLI's own `argv` holds the password when `--auth` is used on the command line (the CLI
already warns about this; `--auth-file` avoids it). The assertions exclude the CLI process itself.

### Anomaly

In the first run of the new test file, one of its two graceful stops (the default-mode launch)
did not complete within the 90 s timeout after CTRL_BREAK: the test then killed the CLI and the lock
file was left behind. It did not recur in the 18 graceful stops since (3 more full test runs, one
default-class run, 11 single launches from a debug driver). Not explained. The test now fails with an
explicit "Ctrl+C did not stop the CLI" message if it happens again.
